- Clarify that branch-derived fallback is allowed only when `.active-spec-path` is missing, not when the marker exists but is unreadable, empty, or points to an invalid path. The intent says derivation is fallback only and marker-present behavior must stay unchanged; without this, an implementation could silently bypass corrupted marker state and change operator-visible failure semantics.

- Clarify the refusal behavior for matched spec directories that do not contain `index.md` and do not reduce to exactly one markdown spec file. The draft defines the positive resolution cases but does not state the negative case, leaving room for arbitrary file selection in multi-file directories. The intent requires resolution to a specific on-disk spec file before completeness and merge checks.

- Make the branch-to-spec matching precedence explicit enough to remove inference: search homes in `plan.targetDir` then `v1/spec` then `v2/spec`, and within a home prefer the direct branch match before any timestamp-stripped `plan/` directory match. This is load-bearing because different precedence choices can resolve the same branch to different specs, and the intent calls for reusing the established cleanup/archive mapping rather than inventing new triage-specific behavior.

- Expand the spec’s observable `--merge` coverage so the finalized behavior is not framed as worktree-name-only. `--merge` accepts resolved targets beyond a named worktree, and the spec should make clear that markerless fallback applies after target resolution in that shared finalization path. This keeps the spec aligned with the intended operator surface and avoids a gap between documented entry forms and tested/accepted behavior.
