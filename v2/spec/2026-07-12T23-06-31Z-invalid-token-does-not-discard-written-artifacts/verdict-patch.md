## Verdict

**Finding 1 (missing-token + satisfied-contract records token `done`, not `no-work`): No action required.** This is the literal, explicit behavior specified in subspec 00 ("Missing token: evaluate the step's contracts; all pass → `complete` with token `done`"). A silent agent makes no claim of "no work found," so there is no signal to recover that distinction from. This is spec-authorized, not a defect.

**Finding 2 (workflow snapshot conflates `invalid_token`-caused stops with operator-initiated pauses): Upheld — must be fixed.**

Subspec 01 makes `invalid_token` runs finish with `resumable: true` and a persisted status of `paused` (reusing the existing `RunStatus`, per the explicit decision not to add a new `WriteLoopOutcomeKind`). But `stoppedOutcomeForRun` (`v2/src/execution/workflow-list-snapshot.ts` or equivalent) currently treats any `status === "paused"` run as an operator-initiated pause, without inspecting the last attempt's `outcomeKind` — even though the same function already drills into `outcomeKind` to distinguish sibling cases (`blocked` → `contract_miss` vs `blocked`; `failed` → `iteration_timeout` vs `invocation_failure`).

**Required outcome:** the workflow-list/daemon snapshot must distinguish a run paused because of an undecidable `invalid_token` outcome from a run paused by explicit operator action (`pauseSignal`). Concretely: `stoppedOutcomeForRun` (or its equivalent) must check `run.attempts.at(-1)?.outcomeKind === "invalid_token"` when `run.status === "paused"`, mirroring the existing `blocked`/`failed` drill-down pattern, and surface a distinct terminal-outcome value for that case rather than uniformly reporting `"paused"`.

**Rationale:** Subspec 01's decision to avoid a new `WriteLoopOutcomeKind` governs the loop's own result type — it does not authorize losing operator-visible fidelity in the daemon/TUI snapshot layer, which already has the mechanism (`outcomeKind` inspection) to preserve this distinction for other statuses. Without this fix, an operator can no longer tell, from the run list, whether a run is sitting paused because they paused it or because the agent produced an undecidable token — a real regression in observability introduced by this spec's own resumability change. This does not require adding a new `WriteLoopOutcomeKind` and stays consistent with subspec 01's stated scope boundary.
