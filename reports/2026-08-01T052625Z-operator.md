## Defects found while dogfooding

**Pipeline approval did not gate (found, seeded, fixed).** On an intent fan-out,
`jarvis pipeline approve <id> <stage> <branchKey>` marked the named branch approved and then
dispatched *every* branch's next stage, including siblings whose own gate still read `awaiting`.
The prematurely-dispatched branch failed (correctly — its prerequisite was unmerged), and
`pipeline resume` then refused `multiple_failed_stages`, so the whole pipeline was unrecoverable
and the work finished through `jarvis run workflow`. Seed
`pipeline-approval-releases-the-wrong-branch`, fixed in [#2447](https://github.com/cbrenner04/jarvis/pull/2447).

**The intent landing contract rejects wrapped bullets (seeded, open).** A `## Prerequisites`
bullet wrapped across lines fails the contract with `must list prerequisites as one bullet per
line`. Valid Markdown; the contract reads raw lines. Blocked two intent runs, both recovered only
by hand-unwrapping the staged file and `jarvis run resume`. Same defect class as row 2 above.
Seed: `intent-landing-contract-rejects-wrapped-bullets`.
