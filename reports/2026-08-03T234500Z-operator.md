## The fan-out regression, found and fixed

[#2577](https://github.com/cbrenner04/jarvis/pull/2577) opened red: `daemon-pipeline-resume.test.ts`
— `"resume returns after admission before async continuation runs"` — failed 3/3 on the branch and
passed on `main`. Revert-bisect isolated it to `pipeline-execution.ts`, and subspec 01 scopes resume
explicitly **out**, so it read as unintended fallout.

It was not a product regression. Instrumenting the walk showed the stage dispatched normally and
then hung forever inside `dispatchPipelineStage` at `await wait(entryRunId)`. The cause was the test
double:

```ts
let settleFn: (() => void) | undefined;
const factory = createBindingFactory(({ cwd }) => new Promise((resolve) => { settleFn = () => …; }));
return { factory, settle: () => settleFn?.() };
```

`settleFn` is only assigned **when the binding is invoked**, so a `settle()` that lands before the
write step starts is silently discarded and the promise never resolves. The test asserts the stage
is still `pending` and *then* settles — it depends on the continuation starting in that window.
`main` passed on timing luck; the concurrent-dispatch change moved invocation past the `settle()`
call and the signal was dropped. Latching the double (record the request, release on invocation)
makes it order-independent: green 3/3, and the whole gate green.

## Two inert mutation directives, recorded not shipped

Applying all four `@mutate` directives by hand: the two on branch-scoped artifact lookup kill
correctly; the two on concurrency are **inert** and leave `pipeline-execution.test.ts` at 73 pass /
0 fail. The task arrays are built with `.map()`, which starts every promise eagerly, so awaiting
them serially changes nothing.

Making them real needs lazy thunks with the concurrency in the awaiting line. That was prototyped
and works — but the serialized form then *deadlocks* the fixture rather than failing it, and
mutation verification has no timeout and no abort wiring, so a hanging directive would stall a write
step indefinitely. `try/finally` around the assertions did not clear it. The honest remaining work
is a fixture change (bounded waits so serialization fails fast), so those two criteria are
**unticked** with a `## Blocker` recording the evidence, rather than ticked hollow. Production
concurrency is unaffected; both regressions pass against it.

Also recorded: subspec 00 decided to "drop `sharedStageArtifacts` carry-forward into suffix
`runAuthoredStages`", but the implementation keeps passing it and gates it internally. Equivalent in
effect, covered by a working mutation pin, but not what the decision says.

## The deadlock that a single hand-gate missed

After the resume fix the whole gate ran green locally, so #2577 went ready — and CI killed
`pipeline-end-to-end.sandbox-unrunnable.test.ts` at its 3-minute budget. It reproduces: **1 run in
3** on the branch hangs, while `main` is 4/4 green in ~2s. My clean hand-gate was the lucky
two-thirds.

Concurrent sibling dispatch can deadlock a real end-to-end pipeline. That is a harder failure than
the inert pins, and it is the reason the branch is back to draft. The lesson worth carrying: for a
concurrency change, one green run of the affected file proves nothing — run it repeatedly before
calling it green.

  salvage.
