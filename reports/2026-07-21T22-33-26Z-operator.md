## The session's central finding

**v2 was not running review at all.** `resolveReviewPasses` in v1 falls back to `modes.review.passes = 1`, so every `jarvis1 run` gets a review pass. v2's primary presets used `?? 0` — and the intended defaults (1 pass; debate, light for intent) existed only on the **deprecated** `*-reviewed` alias builders. When those became legacy aliases, the pass count did not move across; the behavior default did.

So every v2 implement driven by the documented command ran unreviewed, and had done for some time. That is the answer to "why does v2 keep shipping defects that v1 didn't."

Fixed this session: `implement` → 1 debate pass (#1888), `intent` → 1 light pass (#1892). `plan` remains queued. Reviewers also now receive the merge-base unified diff instead of a `--stat` summary (#1894).

Both of those were found by reading the prompt templates, not by guessing.

## Defects caught before merge

Every one had green CI and fully ticked acceptance criteria. Two also passed the mutation gate.

- **#1880 — fatal.** The daemon called `getExecutableTreeDigest(import.meta.dir)`; git resolves
  pathspecs against cwd, so from `v2/src/daemon` it matched nothing and the digest was `sha256("")`
  on every checkout. Every dispatch would mismatch, bounce, mismatch, exit 1 — permanent refusal
  with a live run. Strictly worse than the bug it fixed.
- **#1872 — blocking.** Publication marked rows `in-progress` for the finalization tail, but only
  gate and mutation failures restored a terminal status. `ready_flip_failed` and
  `runtime_smoke_failed` rows were stranded `in-progress` forever, hanging `run wait`.
- **#1859 — silent review skip.** Checkpoint reuse keyed on `(project, branch, stepId)` with no
  invocation identity, so a second implement dispatch inherited the prior verdict and skipped patch
  review entirely.
- **#1858 — projection regression.** A `!step.durable` exclusion also caught durable intent-stage
  review steps, rendering live rows as `invocation_failure`.
- **#1894 — CI-only.** A real-git fixture committed without `user.email`/`user.name`: passes
  locally off the operator's gitconfig, fails on every CI runner.

## Verification blind spots (seeded)

- `runtime-smoke-cannot-observe-component-interaction` — `isRunnableEntrypoint` matches three literal
  paths; #1880's diff matched none, so smoke returned `not-runnable` and passed vacuously. Its
  command is `--help`, which could not compare two digests anyway.
- `test-doubles-that-call-production-code-encode-the-fix` — `makeIpcClient` computes its reply using
  the production `advanceLoadedRevision`, so the double agrees with production by construction.
  Reverting the entire dispatch guard failed **0 of 144 tests**. The mutation gate was fed a rigged
  oracle.
- `mutation-verifier-flips-operators-in-prose` — `prompts/**` is not excluded from production, so
  comparison-operator flips are applied to markdown; `<base>` became `>=base>` and failed a run.
- Cross-revision compatibility is unverified: nothing pairs revision N's CLI with N−1's daemon. Per
  operator, this is a daemon design problem, not a testing one — see
  `key-the-daemon-by-executable-digest`.
