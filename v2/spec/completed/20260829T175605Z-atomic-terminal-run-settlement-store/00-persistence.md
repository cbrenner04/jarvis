# Persistence

Authoritative for persistence: acceptance criteria, documentation updates, and material decisions in this file supersede `intent.md` where they differ.

## Problem

`StateStore` can make a run terminal through `setRunStatus`, `commitGuardedKill`, `commitCompletionBoundary`, and orphan reconciliation while PR evidence is written through separate `setPrEvidence`. A reader can therefore observe a terminal `runs.status` (and `finished_at`) without the PR pair or other settlement fields the operator needs to act on that outcome. This slice adds one transactional settlement primitive only; partial terminal visibility remains reachable through those legacy callers until daemon and execution intents migrate. Downstream intents need that primitive before caller migration lands.

## Decision ledger

- `commitTerminalRunSettlement` is the single transactional writer for terminal `runs.status`, `finished_at`, optional durable `terminalCause`, optional `prNumber`/`prUrl`, and optional `terminalFailureDetail`; rules out documenting hand-ordered `setPrEvidence` then `setRunStatus` as the persistence contract for new terminal-evidence paths.
- Settlement input accepts only `isTerminalRunStatus` values; `paused`, `in-progress`, `queued`, and `budget-soft-stopped` stay on `setRunStatus`; rules out coupling nonterminal transitions to terminal evidence columns.
- `terminal_cause` TEXT stores a `WriteLoopOutcomeKind` string — the durable settlement cause aligned with log `loop_finished.loopOutcomeKind`; settlement input accepts optional `terminalCause?: WriteLoopOutcomeKind | null` (execution callers pass their `loopOutcomeKind` here), validated with `isWriteLoopOutcomeKind` on write; rules out a separate cause vocabulary from execution's settlement contract.
- `terminal_failure_detail` stores nullable JSON TEXT in the `InvocationFailureDetail` shape (same family as attempt `invocation_failure_detail`); valid examples include `{ failureKind: "quota", bindingAttempts: [] }` and `{ failureKind: "timeout", bindingAttempts: [], exhaustedRoleTimeout: true }`; `mapRunRow` parses valid JSON into `terminalFailureDetail`, sets `terminalFailureDetail: null` and `terminalFailureDetailCorrupt: true` when the column is non-null but not valid JSON (following `readyGateRepairFenceCorrupt` / `retainedFinalizationCheckpointCorrupt` precedent); rules out silent coercion of corrupt settlement detail.
- Omitted optional evidence fields leave their columns unchanged on the targeted row; explicit `null` for `prNumber`/`prUrl`/`terminalCause`/`terminalFailureDetail` clears that column; rules out wiping a prior PR pair when settling `killed` without publication fields.
- `prNumber` and `prUrl` use independent per-field omitted-vs-null semantics (unlike `setPrEvidence`, which always writes both); publication paths should supply both when publishing; rules out treating the PR pair as an atomic unit in settlement input.
- `finished_at` is stamped to `Date.now()` inside the settlement transaction when the new status is terminal, matching today's `setRunStatus` terminal semantics; rules out a separate finish-metadata write outside the settlement transaction.
- Migration `029-run-terminal-settlement-columns` adds nullable `terminal_cause` TEXT and `terminal_failure_detail` TEXT on `runs` with no backfill; pre-migration rows read `terminalCause`/`terminalFailureDetail` as `null`; rules out log-only cause as the durable settlement contract for store readers.
- Settlement performs at least two in-transaction UPDATE statements (terminal `status`/`finished_at` first, then evidence columns) so `beforeSecondWrite` runs after the first statement; rules out a single multi-column UPDATE that would make the fault-injection AC untestable.
- `commitCompletionBoundary`, `commitGuardedKill`, `beginRunReconciliation`, and legacy `setRunStatus`/`setPrEvidence` remain callable in this slice; persistence supplies the primitive only and does not own caller admission guards; rules out folding guarded-kill predicates or completion-boundary idempotence into this operation.
- Repository-wide production caller guard deferred to `execution-terminal-run-settlement-invariant`; rules out failing this independently mergeable foundation on known legacy terminal writes.
- `beforeSecondWrite` is a test seam only, mirroring `commitCompletionBoundary`'s `beforeRunUpdate`; rules out production `setInvert*ForTest` hooks.
- Deferred to first consumer: idempotent re-settlement when the row is already terminal with the same status — pin when daemon reconciliation or guarded-kill migration needs it.

- Add `state-store.test.ts` coverage for happy-path persistence, optional-field omission vs explicit clear, nonterminal refusal, unknown-run refusal, pre-migration null reads, corrupt `terminal_failure_detail` load, and mid-transaction rollback via `beforeSecondWrite`.
