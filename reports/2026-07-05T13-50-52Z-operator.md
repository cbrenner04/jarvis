## Observations

- **CPU-contention flakes from a concurrent v1-overhaul terminal.** The operator flagged a parallel terminal running a v1 spec overhaul at session start. Its work included an **orphaned `bun test` process (pid 33500, reparented to init) that ran at 100% CPU for 9–11+ hours** — a genuine stray, not intentional load. This caused repeated local gate flakes (`preflight.sandbox-unrunnable.test.ts` git-ls-remote-stall, `preload.sandbox-unrunnable.test.ts` PATH check) during `jarvis1 plan`/`run` completion gates. Recovery pattern: isolate-retest the specific failing file(s); if green in isolation, the failure is contention, not a regression, and Jarvis's own fix-up/retry ladder (or a manual isolated retest + CI-green confirmation) is sufficient — no code changes needed. Flagged the stray process to the operator; not killed (not this session's process to touch).
- **A separate, unrelated stuck-CI pattern on GitHub's own runners.** Independent of local contention, the `Test (v2)` CI step got stuck with zero step progress for 15–20+ minutes on PRs #1045, #1047 (twice), #1048 (twice), and #1049 — while every other run of the same step elsewhere completed in under a minute. Recovered every time via `gh run cancel <id>` + `gh run rerun <id> --failed`; each rerun then completed normally. This recurred often enough (6 incidents across 4 PRs) that it's worth a harness-suggestion seed rather than treating each as a one-off.
- **Parallel `jarvis1 plan` runs on the same file need three-way merge reconciliation before merge.** `human-loop-behavior` and `review-debate-behavior` both extended the same `WorkflowStep` discriminated union in `v2/src/execution/workflow-runner.ts` (adding `human` and `review-debate` behaviors respectively). `review-debate-behavior` merged first; `human-loop-behavior`'s completion left its PR (#1047) `mergeStateStatus: DIRTY`. Recovery: `git merge --no-commit origin/main` in the worktree, delegate the mechanical reconciliation to a subagent (unify the type union, dispatch logic, snapshot-building), then **independently re-verify** (typecheck + `bun test:v2`/`test:integration:v2`) before committing — do not trust a subagent's local pass alone. The subagent's reconciliation was correct in substance but needed two follow-up rounds of `bunx biome check --write` (import ordering, then `executeWorkflow`'s cognitive complexity 25>24 from the merged three-way dispatch) before CI went green — strict CI Biome catches issues a quick local pass can miss.
- **`review-debate-behavior`'s own review-debate actuator caught a real regression it introduced**, not just a flake: two `v2/src/cli.test.ts` tests leaked the operator's real `~/.jarvis/config.json` into a default-bindings assertion (expected 1 binding, got 4). The actuator's own verdict fixed it correctly (`machineConfigPath: absentMachineConfigPath()`) and separately caught+reverted out-of-scope `v1/spec` edits that had been bundled into the branch by mistake (an unrelated in-flight spec's sequencing notes). Confirmed both were genuine fixes, not papered-over symptoms, before merging.
- **`tui-human-loop-controls`'s implementation was clean** — a purely additive extension of the already-merged `workflow-runner.ts` (adding an `onReviewDebateProgress` observer callback), no merge conflicts, no Biome follow-ups needed.
