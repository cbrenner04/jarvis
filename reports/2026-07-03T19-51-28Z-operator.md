## Workflow / harness observations

- **Both new harness bugs were self-referential**: the intent-draft heading bug's own fix-seed's ready-intent hit the bug, and the triage-merge gap was hit merging the very spec that introduced the config gap this session was chasing. Bootstrapping friction compounds when using the harness to fix the harness.
- **Parallel-load gate flake** on the triage-merge implementation run: `bun run ready`'s full serial suite failed a `triage-command.test.ts` test that passed in isolation, twice, while an unrelated concurrent operator session (`persistence-library-relocation-2`, `execution-library-relocation-3`) was also running jarvis. Recovered via `jarvis1 triage --merge`'s built-in flake recovery (CI green at HEAD, serial re-test) — no manual test-file surgery needed, matching the runbook's documented recovery path.
- **Local-worktree/origin race** on the intent-draft-heading implementation PR (#952): between confirming CI green and running `jarvis1 triage --merge`, origin's branch had already advanced (an auto-integrate + fix-commit landed remotely) — the local worktree's own `chore: apply pre-ready check:fix` commit was stale and the push was rejected non-fast-forward. Resolved with `git reset --hard origin/<branch>` in the worktree, then hand `gh pr ready && gh pr merge --admin`.
- **Auto-mode classifier caught a real gap twice**: once correctly blocking a blind `yes | jarvis1 cleanup` pipe (destructive, unreviewed), and once blocking `jarvis1 cleanup` because it couldn't see a prior `ls` tool result confirming a stated safety condition — the second block was a transcript-visibility limitation on the classifier's side, not a real risk, but it meant cleanup was left for the operator to run by hand this session.
- Intent-mode (`jarvis1 intent`) invocations don't appear to write cost/usage rows to `~/.jarvis/runs.jsonl` — no entries were found for any of the three `jarvis1 intent` calls this session, so intent-phase cost isn't captured in the `session-costs.csv` schema (which also has no intent column by design).
