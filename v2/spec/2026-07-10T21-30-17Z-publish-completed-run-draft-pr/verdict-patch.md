Required outcomes:

1. **Resume must not silently mask a failed publish as success.** After a successful completion commit followed by a failed/interrupted publish, resuming the run must re-attempt publication rather than short-circuiting into the "nothing to commit" no-op path and returning stale success. The gate that decides whether to invoke the publisher must distinguish "HEAD already holds the pending commit but publish hasn't succeeded" from "truly nothing changed." This is required by the spec's own resume guarantee ("resume retries without duplicating the completion commit or an open PR") and by AC 6 — a resume that reports success without actually publishing violates that AC.

2. **Retry/backoff must use injected seams, not real time or hardcoded stdout.** The spec's decision to "inject subprocess, delay, retry-notice, and `gh`-readiness seams" is load-bearing (this is explicitly the first, precision-pinning consumer of the v2 retry policy) and is echoed in the ACs. The implementation must expose and use an injectable delay function (no busy-wait or real sleep), an injectable retry-notice callback (no direct `console.error`), and a distinct `gh`-readiness seam (not folded into a generic `gh` command seam). Tests must exercise retries via these injected seams with no real elapsed wall-clock delay and no live `gh`/git calls. This is a direct, verifiable gap against a decision and AC the spec explicitly pinned — not a defensible scope cut.

3. **Workflow-level publish/commit failures should carry their error message**, not just a boolean/opaque failure, so the workflow result surfaces the same diagnostic detail the standalone path already provides (`completionCommitError`). Align the two call sites so operators can debug a failed workflow publish the same way they debug a failed standalone one.

Rationale: outcomes 1 and 2 directly undermine acceptance criteria the spec pins as verifiable (resume correctness, injected-seam testability) — both are core to why this spec exists (per its own verdict-plan history, this work *creates* the retry seam, so its seams must be real and testable, not asserted). Outcome 3 is a smaller correctness/consistency gap worth closing but doesn't block on its own if 1 and 2 are fixed.
