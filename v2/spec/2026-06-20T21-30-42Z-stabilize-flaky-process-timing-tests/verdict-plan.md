# Verdict

The spec is structurally sound and correctly scoped (test-only, code-under-test preserved, no global timeout/parallelism changes). It does not need rework. But several findings are upheld and require tightening of the spec's definition of "done," its preservation list, and its scope boundaries. Required refinements:

1. **Redefine "done" as structural determinism, not statistical repeatability.** The current language ("pass repeatably under load," "repeatably under load") promises something a single completion-gate run cannot prove — you cannot demonstrate a flake is gone by passing once. The spec's own sanctioned mechanisms (poll-until-a-condition with a generous deadline, serialization) are structural: they remove the wall-clock dependency by construction. State the completion signal accordingly — the stabilized assertions no longer read scheduler timing as a pass/fail axis — so a single green run plus that structural argument is a coherent done-definition. This also resolves the circular-baseline concern (a "green modulo the flakes" prerequisite gives no trustworthy statistical baseline; structural determinism needs none).

2. **Demote flake reproduction from a gating step to confirmatory.** Both subspecs make "reproduce the flake under the loaded parallel suite" a hard first checklist item and tie mechanism choice to "the observed cause," yet the prerequisites admit reproduction is luck-dependent and may not surface in a given run. The timing dependency is already diagnosed by inspection (fixed-time `waitFor` deadlines; the `elapsedMs <= 7200` bound). Frame reproduction as: diagnose the dependency from the code, repro opportunistically if it surfaces, but do not block progress on a red run that may never appear.

3. **Add the watchdog promptness assertion to the preservation list.** The `elapsedMs <= 7200` bound encodes that the watchdog *fired early* rather than waiting out the full timeout — real coverage, and the assertion most tempting to simply widen into meaninglessness. The preservation list currently names `watchdog_descendants_alive` / `watchdog_pgid` / `last_output_age_ms` but omits this. State explicitly that a stabilized form must still prove early interruption, not just relax the upper bound.

4. **Add a decision that the mechanism must not mask a correctness regression.** The existing decisions guard only against deleting or weakening checks. A retry-on-timing wrapper can also hide a genuine implementation regression that manifests as a timing failure — a coverage cost distinct from deletion. Name this constraint; it correctly deprioritizes the retry wrapper relative to poll-until-bounded-deadline (which still fails a genuinely broken implementation).

5. **Bound subspec 01's scope to the named same-cause set; drop the open-ended clause.** Subspec 01 pre-lists three watchdog tests while the intent's evidence cites one, and adds "any other watchdog test shown to flake from the same cause" — pulling in never-observed tests and leaving the boundary to a repro step that may not fire (see #2). Frame the additional tests as same-cause candidates to stabilize only if they exhibit the fixed-time dependency, and remove the unbounded "any other test" language so scope is a named set.

6. **Minor — restore conditional documentation language and note serialization feasibility.** The subspecs hardened the intent's hedged "only if a test-only helper changes an observable testing contract (likely none)" into a flat "None." If the chosen mechanism introduces a shared serial/helper convention, that is plausibly a testing contract warranting a `v2/docs/v1-behaviors.md` line; restore the conditional. Separately, the "serialize just these tests outside the parallel pool" candidate assumes per-test opt-out is supported by the test runner — add a one-line feasibility caveat or position it as a fallback below poll-until so an implementer does not burn an iteration discovering it is unavailable.

Rationale: these refinements align the spec's stated acceptance with what its already-chosen structural mechanisms can actually deliver (a verifiable completion signal under a one-shot gate), and they close coverage-erosion and scope-creep gaps so the fix preserves the behaviors the tests exist to catch. None alters the spec's scope or structure.
