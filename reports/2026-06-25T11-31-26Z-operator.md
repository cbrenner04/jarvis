## Observations — workflow + tooling + harness

**What worked:**

- **Sequential run stage, merge-between** cleanly avoided conflicts — every
  run-stage spec edits `v1-behaviors.md` + `run-loop.md`, so concurrent runs
  would have collided on docs. Plan + intent stages parallelized fine (disjoint
  spec dirs).
- **Dogfooding paid off:** `converge-and-ready`'s own exit-11 auto-ready readied
  its PR head when its review phase quota'd — the feature working on itself.
- Intent splits were sensible (review-actuator → prevention+recovery; the 3
  issue-seeds → 7 well-scoped behaviors).

**Harness gaps hit (each a manual intervention → now seeded):**

- **`lint:md` on generated markdown** blocked auto-ready 3× — intent
  ready-intents (MD012/MD018) and a plan `index.md` (MD034 bare URL) left PRs
  #509/#511/#512 stuck draft until hand-fixed. Seeded
  (`generated-markdown-fails-lintmd-blocks-auto-ready`).
- **`repo:` line in plan-generated `index.md`** made `jarvis run` reject the
  spec (`spec repo must be an absolute path`), blocking auth-error + dep-adding
  until hand-stripped (PR #522). Seeded
  (`plan-emitted-repo-line-in-index-breaks-run`).

**Friction that resolved itself / recovered:**

- **Mid-session quota exhaustion** (claude + cursor) during review phases →
  exit-11 review-incomplete on `sync-ready` and `converge-ready`; local
  fallbacks (opencode/aider→ollama) couldn't connect. Both PRs were
  auto-readied and merged — implementation intact, only the review debate
  skipped. (Recovered without intervention beyond review.)
- **Flaky watchdog timing test** (`run.sandbox-unrunnable.test.ts`
  `last_output_age_ms`) failed `review-convergent`'s baseline gate under
  parallel load (exit 1); re-ran in isolation (green) → manual finalize. This is
  precisely the friction intake issue #519 / the ready-gate-flake seed targets.
