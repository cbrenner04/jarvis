# Plan-draft enclosing-test validation

## Problem

`linkDirectivesToCriterion` links a `// @mutate` directive only when the criterion text contains the directive's enclosing `test()`/`it()` title (`criterionText.includes(directive.pinTitle)`, case-sensitive, no all-directives-in-file fallback). Authoring guidance (#2655) and plan-review advisory hollow-pin (#2660) do not block plan-draft, so criteria omitting the pin title land and go hollow at implement time even when the directive and pinning resolution are correct.

## Decisions

- Plan-draft MUST hard-reject staged subspecs whose non-human-only authored `Mutation checkpoint:`, `Keystone checkpoint:`, or directive-shaped `@mutate` criterion does not name an enclosing `test()`/`it()` title resolvable in the referenced pinning file — rules out advisory-only hollow-pin (#2660) or implement-time-only detection. Plan-draft scans **authored** criteria (checked and unchecked) in staged `NN-*.md`; implement still gates on ticked criteria only.
- Rejection names the offending criterion and the missing or unresolvable test title — rules out a generic hollow-risk warning the author can ignore.
- Plan-draft enclosing-test validation does **not** prove the criterion names the directive's `pinTitle` — only that criterion block text `includes` at least one title that exists in the resolved pinning file (case-sensitive). Wrong-but-existing titles and titles from a different test in the same file remain implement-time hollow — rules out full linker parity or directive-pinTitle enforcement at plan-draft.
- Validation runs in v2 `validatePlanDraft` / `composePlanDraftArtifactCheck` on the staged spec tree after `normalizePlanDraftSpecDir` succeeds — rules out plan-review-only hard enforcement; plan debate hollow-pin stays advisory.
- `validatePlanDraft` and `composePlanDraftArtifactCheck` take `worktreeRoot` alongside `specDir`; `executePlanDraftWrite` passes its in-scope `worktreePath` — rules out pinning checks against spec-dir alone or a caller-side parallel validator.
- Scan `## Acceptance criteria` mutation-checkpoint-shaped, keystone-checkpoint-shaped, and directive-shaped `@mutate` criteria in staged `NN-*.md` subspecs via `shared/mutation-checkpoint-criteria.ts` selectors (checked and unchecked; skip human-only); exclude `index.md` and `intent.md` — rules out index routing noise.
- Enclosing-test check aligns with implement-time linking on the `includes` primitive: when pinning-file resolution succeeds to a readable on-disk file, criterion block text must `includes` at least one pin title extracted from that file (case-sensitive) — rules out the weaker backtick/quote heuristic alone (#2660) and deferring to implement for titles absent from a resolved pinning file (#2697 scope is existing titles omitted from criterion text, not greenfield test authoring).
- Pin-title extraction collects **all** resolvable `test()`/`it()` titles in the resolved pinning file (including multiline `test.each` continuation titles per shipped #2696), reusing verifier pin-title scan patterns — no forked regex and not directive-only title lists — rules out weaker directive-only extraction or divergent title parsing.
- Pinning-file resolution reuses verifier pin-path rules (`pinningTestReferenceFromCriterion`, path-qualified vs basename, extension tolerance from `mutation-checkpoint-pin-resolution`) — rules out divergent plan-draft vs implement resolution.
- When a mutation-checkpoint-shaped, keystone-checkpoint-shaped, or directive-shaped criterion has **no resolvable pinning-file reference** (no backticked pinning path), plan-draft **skips** enclosing-test validation for that criterion and implement still owns refusal — rules out silent hard-reject vs ambiguous skip for no-reference criteria.
- Pinning-file resolution failure (ambiguous basename, missing on-disk file) or pinning file unreadable/unparseable after path resolution skips the plan-draft enclosing-test check for that criterion — rules out plan-draft duplicating implement-time pinning refusal, blocking greenfield missing files, or hard-failing IO/parse errors at plan-draft.
- First violation wins: staged `NN-*.md` walk order then criterion block order within `## Acceptance criteria`; no aggregation — rules out multi-criterion diagnostic bundles.
- Rejection propagates through existing plan-draft `contract_miss` plumbing at normalizer parity: `failedContractId` stays `"artifact.exists"`; `failureReason` is structured free text with `criterion:`, `reference:`, and `reason:` lines (`missing_enclosing_test_title` when criterion text includes no extracted file title; `unresolvable_enclosing_test_title` when criterion text includes only title(s) absent from the file), naming the offending criterion text and the missing or unresolvable title; the same string surfaces on write-loop `contract_miss_detail.failureReason` and in the harness-appended staged `intent.md` `## Blocker` — rules out a new contract id, implement-time-only messaging, or `failureReason`-only projection weaker than normalizer rejections.
- Enclosing-test `contract_miss` is terminal through `composePlanDraftArtifactCheck` (no durable-dir shape fallback when staging fails with an enclosing-test reason), same as other non-`plan.draft.shape` rejections — rules out reprompt/fallback via durable pass.
- Implement-time verifier and hollow messaging unchanged — rules out re-tuning `contract_miss` at implement in this slice.
- v1 `validateDraftOutput` out of scope — rules out v1 parity here (cf. unsatisfiable-AC v2 deferral).
- Out of scope: multiline-title resolution and extension-tolerance algorithm changes (shipped #2696).

## Tasks

- Extend `validatePlanDraft` and `composePlanDraftArtifactCheck` in `v2/src/execution/write.ts` to accept `worktreeRoot`; wire `executePlanDraftWrite` to pass `worktreePath`.
- After successful `normalizePlanDraftSpecDir`, walk staged `NN-*.md` subspecs and run enclosing-test validation on mutation-checkpoint-shaped, keystone-checkpoint-shaped, and directive-shaped criteria using shared selectors.
- Reuse or export verifier pinning resolution and pin-title extraction (all resolvable `test()`/`it()` titles in file via verifier scan patterns, including multiline `test.each` continuations).
- Add `write.test.ts` regressions for mutation-checkpoint, keystone, and directive-shaped omission rejection; well-formed pass; missing pinning-file skip; no-reference skip; guard inversion on the enclosing-test check; and `write-loop.test.ts` (or equivalent) coverage for `contract_miss_detail` / staged `intent.md` `## Blocker` projection when enclosing-test validation fails.
- Update operator and authoring docs per Documentation updates.

- [x] `write.test.ts` drives plan-draft completion when staged mutation-checkpoint, keystone-checkpoint, and directive-shaped criteria each name a resolvable enclosing test title in their resolved pinning files; asserts no enclosing-test `contract_miss`; fails against the pre-fix code.
- [x] `write.test.ts` drives plan-draft completion when a staged mutation-checkpoint criterion references a pinning file missing on disk (resolvable reference, file absent); asserts enclosing-test validation produces no finding; fails if plan-draft hard-rejects missing pinning files.
- [x] `write.test.ts` drives plan-draft completion when a staged mutation-checkpoint-shaped criterion has no resolvable pinning-file reference; asserts enclosing-test validation produces no finding; fails if plan-draft hard-rejects no-reference criteria.
