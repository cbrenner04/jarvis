# Branch-grouped pipeline subtree

Authoritative for implement runs: acceptance criteria, documentation updates, and material decisions in this file supersede `intent.md` where they differ.

## Problem

`buildStageNodes` (`v2/src/tui/tui-monitor-pipeline-tree.ts`) maps `snapshot.stages` one-to-one onto stage nodes in durable order, so a fanned-out `full-review` pipeline paints `intent`, `approve-intent` ×(1 default + N branches), `plan` ×(1 + N), … — branches interleaved by stage position. At 3 branches that is ~20 rows in which no row says "this seed split into 3 intents, here is each intent's progress"; dogfooding showed the operator could not tell the rows were one seed split three ways. The post-split `default` rows in that list are pure noise: `admitFanOutBranches` writes `skipped` to every one and nothing ever runs on them.

## Decision ledger

- Pipeline subtree is pipeline → pre-split stages inline → one branch node per fan-out `branchKey` → that branch's post-split stages in position order. Rules out flat stage-position ordering.
- Fan-out is derived from the snapshot: `fanOutSplitPosition(snapshot)` is the lowest `position` carrying a non-`default` `branchKey`, or `null`; a stage is post-split when `position >= splitPosition`. Rules out a new split marker on the `pipeline_list` wire.
- Branch node id is `monitorPipelineBranchNodeId(pipelineId, branchKey)` = `` `${pipelineId}:${branchKey}` ``; stage node ids keep `monitorPipelineStageNodeId`. Rules out re-keying stage nodes under the branch, which would drop a live selection on the refresh that introduces the branch level.
- `MonitorPipelineTreePipelineNode.stages` narrows to **pre-split stages only** and a new `branches` field owns the rest; `pipelineStageNodes(pipeline)` is the exported walk over both. Rules out keeping `stages` as a duplicate all-stages array alongside `branches` — two arrays holding the same nodes leaves every reader guessing which one is authoritative.
- Every existing `pipeline.stages` consumer routes through `pipelineStageNodes`. Rules out leaving them on the narrowed field, which would silently make fan-out gates un-approvable and un-expandable.
- Post-split `default` placeholder rows are not built as nodes; pre-split stages, which also run on `default`, still are. This subspec owns the placeholder elision because grouping has no branch node to put those rows under. Rules out filtering every `default` row, and rules out deferring it to the gate-elision subspec.
- Stage nodes are filtered before invocation claiming, so a run joins the first *rendered* stage carrying its `workflowInvocationId`. Rules out claim-then-filter, which would strand a run under an elided row.
- Branch labels: with ≥2 sibling branch keys, strip their longest common leading `-`-segment run, capped so every label keeps at least one segment; a lone branch, or siblings whose first segments differ, render the full key. `tui-pipeline-list-poll` / `tui-pipeline-tree-model` / `tui-pipeline-tree-monitor` → `list-poll`, `tree-model`, `tree-monitor`. Rules out the per-pair reading (longest prefix shared by *any* two siblings), which would strip `tui-pipeline-tree-` from two of those keys and nothing from the third, leaving labels that are no longer comparable.
- Branch summary is derived from the branch's snapshot **records**, not its rendered nodes: first post-split record in position order whose status is not satisfied, else the last record. Rules out deriving it from nodes, which the next subspec's gate elision would silently change.
- Satisfied means `succeeded`, `approved`, or `skipped`. Rules out reusing `isAuthoredStageSatisfied`, which excludes `skipped` and would park a skip-settled branch's summary on a stage that will never move.
- Branch row cells: `label` = stripped label, `branch` = summary stage id, `state` = summary status, `elapsed` = empty. Rules out packing stage id and status into the 12-wide `state` cell, which truncates the stage name away — the one thing the summary exists to show. Accepted cost: the summary stage id drops with the `branch` column below the `TIER_NO_BRANCH` width, and row anatomy retires this grid next (`tui-work-row-anatomy`).
- Deferred to first consumer: branch-row `elapsed` — `tui-work-idle-time` owns work/idle aggregation; pin when it needs it.
- Branch nodes order by first encounter in `snapshot.stages`. Rules out sorting by stripped label, which reorders siblings as the shared prefix changes.
- Branch nodes are expandable (`isExpandablePipelineNodeId`, so `e`, `expand`, `collapse`, and ↓-into-collapsed all reach them) and reveal-on-select adds pipeline and branch ancestors only. Rules out expanding sibling branches.
- Node depth: pipeline 0, branch 1, pre-split stage 1, branch stage 2, runs one/two below their stage. The fixed 2-wide `indent` cell is unchanged for stage and branch rows; deeper run rows spill into `label` exactly as `workflow-child` rows already do. Rules out inventing indentation inside the fixed grid — row appearance is `tui-work-row-anatomy`.
- Stage rows under a branch keep painting their `branch` cell unchanged. Rules out blanking it here; row content is `tui-work-row-anatomy`'s surface.
- The right pane resolves a selected stage's record by `stageId` + `branchKey`. Rules out today's positional `pipeline.snapshot.stages[pipeline.stages.indexOf(treeRow)]`, which grouping and elision desynchronize into wrong-stage detail.
- A selected branch node renders pipeline context plus the full `branchKey`. Branch-grouped detail roll-up stays with `tui-detail-pane-structure`.
- `dockHintLine` derives expandability from `isExpandablePipelineNodeId` over the joined pipeline nodes instead of reconstructing stage node ids from raw snapshots. Rules out a third place that has to learn the branch id format.
- Steering codes are reused, not extended, for a branch selection: `approve`/`reject` report `not_awaiting_stage`, `resume` reports `not_pipeline`. Rules out a new `branch_node` code for a row that steering was never going to accept.
- A pipeline with no fan-out builds no branch nodes and renders exactly as today. Rules out a synthetic single `default` branch node.
- Assertions run through the pure builders and the injected input hook; no rendered-ink frame assertions (`v2/docs/test-writing.md` § TUI test strategy).
- Out of scope: gate elision and the intent-split yield (subspec 01), row appearance (`tui-work-row-anatomy`), detail-pane structure (`tui-detail-pane-structure`), work/idle elapsed (`tui-work-idle-time`).

## Prerequisites

- `buildMonitorPipelineTreeJoin` returns `{ pipelineNodes, adHocNodes, builderRuns }` and `flattenMonitorPipelineTree` emits one ordered node list (`v2/src/tui/tui-monitor-pipeline-tree.ts`).
- `PipelineSnapshot["stages"]` carries `stageId`, `branchKey`, `position`, `status`, `startedAt`, `endedAt`, and `workflowInvocationId` (`v2/src/daemon/pipeline-observation.ts`).
- `admitFanOutBranches` keys one branch per `downstreamInputs` basename and writes `skipped` to each post-split `default` record (`v2/src/daemon/pipeline-execution.ts`).
- `resolveSelectedAncestors` reveals a selection's ancestors and `isExpandablePipelineNodeId` gates `e` / `expand` / `collapse` / ↓-into-collapsed (`v2/src/tui/tui-monitor-pipeline-tree.ts`, `v2/src/tui/tui-entry.tsx`).
- `unwrappedRightPaneSegmentRows` resolves the selected row from `fullTreeRows` and renders pipeline context plus the selected stage record (`v2/src/tui/tui-monitor-lines.ts`).

## Tasks

- `v2/src/tui/tui-monitor-pipeline-tree.ts`:
  - Add `const MONITOR_TREE_DEFAULT_BRANCH_KEY = "default";` and use it in `stageBranchCellValue`.
  - Add `export type MonitorPipelineTreeBranchNode = { kind: "branch"; id: string; depth: 1; pipelineId: string; branchKey: string; label: string; summaryStageId: string; summaryStatus: string; stages: MonitorPipelineTreeStageNode[] }` and include it in `MonitorPipelineTreeDisplayNode`.
  - Add `export function monitorPipelineBranchNodeId(pipelineId: string, branchKey: string): string` returning `` `${pipelineId}:${branchKey}` ``.
  - Add `function fanOutSplitPosition(snapshot: PipelineSnapshot): number | null` collecting `snapshot.stages.filter((stage) => stage.branchKey !== MONITOR_TREE_DEFAULT_BRANCH_KEY).map((stage) => stage.position)` into `branchedPositions` and ending with `return branchedPositions.length === 0 ? null : Math.min(...branchedPositions);` — that return is the keystone-mutation anchor and must stay on one physical line.
  - Add `function isElidedPlaceholderStage(stage: PipelineSnapshot["stages"][number], splitPosition: number | null): boolean` opening `if (splitPosition === null) return false;` and ending `return stage.position >= splitPosition && stage.branchKey === MONITOR_TREE_DEFAULT_BRANCH_KEY;` — that return is a guard-mutation anchor.
  - Add `export function strippedBranchLabels(branchKeys: readonly string[]): string[]` opening `if (branchKeys.length < 2) return [...branchKeys];` (guard-mutation anchor), then splitting each key on `-`, taking the longest common leading segment run capped at `min(segmentCount) - 1`, and re-joining the remainder.
  - Add `const SATISFIED_BRANCH_STAGE_STATUSES = new Set(["succeeded", "approved", "skipped"]);` and a summary deriver over the branch's post-split records in position order whose find reads `const unsatisfied = records.find((record) => !SATISFIED_BRANCH_STAGE_STATUSES.has(record.status));` (guard-mutation anchor), falling back to the last record.
  - Reshape `buildStageNodes` into a builder that computes `splitPosition`, drops `isElidedPlaceholderStage` records **before** invocation claiming, builds stage nodes at depth 1 (pre-split) or 2 (branched) with `workflowTableRowsToRunNodes(stageDepth, …)`, and returns `{ stages, branches }`; `buildMonitorPipelineTreeJoin` spreads both onto the pipeline node.
  - Add `export function pipelineStageNodes(pipeline: MonitorPipelineTreePipelineNode): MonitorPipelineTreeStageNode[]` returning pre-split stages followed by each branch's stages, and route `isExpandablePipelineNodeId` (which also admits branch ids) through it.
  - `resolveSelectedAncestors`: after the pre-split stage walk, walk `pipeline.branches` — branch id → `new Set([pipeline.id])`, branch stage → `new Set([pipeline.id, branch.id])`, and `if (run.id === selectedNodeId) return new Set([pipeline.id, branch.id, stage.id]);` (guard-mutation anchor).
  - `flattenPipelineNode`: emit pre-split stages (and their runs) as today, then each branch node, and that branch's stages (and their runs) only when `effectiveExpansion.has(branch.id)`.
  - Add `export function buildBranchMonitorTreeRow(node: MonitorPipelineTreeBranchNode, selectedNodeId: string | null, leftPaneWidth: number): string` painting `marker`, `indent: "  "`, `label: node.label`, `branch: node.summaryStageId`, `state: node.summaryStatus` through `joinPipelineTreeCells`.
- `v2/src/tui/tui-ink-monitor.tsx`: `renderTreeRow` gains a `branch` case rendering `buildBranchMonitorTreeRow(treeRow, selectedNodeId, leftPaneWidth)` through `renderPrebuiltTreeRow`.
- `v2/src/tui/tui-monitor-lines.ts`:
  - Replace the positional stage lookup with `pipeline?.snapshot.stages.find((stage) => stage.stageId === treeRow.stageId && stage.branchKey === treeRow.branchKey)` — one physical line, the right-pane guard-mutation anchor.
  - Add a `treeRow.kind === "branch"` arm returning pipeline context rows plus `row(untoned("Branch"))` and `detailRows([["branch", treeRow.branchKey]])`.
  - `dockHintLine` computes `expandable` via `isExpandablePipelineNodeId(buildMonitorPipelineTreeJoin(mergePipelineSnapshots(state.pipelineSnapshotsBySocketPath), state.runs).pipelineNodes, state.selectedNodeId)`, dropping the inline snapshot-derived id reconstruction.
- `v2/src/tui/tui-entry.tsx`: route `pipelineIdForSelection`, `approveRejectSelectionError`, `resumeSelectionError`, and `resolveAwaitingStageTarget` through `pipelineStageNodes(pipeline)`; `pipelineIdForSelection` also matches branch ids; `approveRejectSelectionError` returns `not_awaiting_stage` and `resumeSelectionError` returns `not_pipeline` for a selected branch id.
