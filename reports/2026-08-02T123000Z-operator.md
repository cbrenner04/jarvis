## Clearing the mutation gate on #2533

The harness refuses completion one surviving `operator-flip` at a time — eight resume cycles if fixed piecemeal. Sweeping all 20 equality operators on the diff's changed production lines found **12 killed, 8 surviving**, splitting three ways:

- **Two were real coverage gaps in new code.** Nothing asserted that a reconnected owner socket
  re-issues the selected run's `wait`, or that a terminal run ageing out of the retention window
  clears the selection. Both now have tests.
- **Three were genuinely unreachable** and were removed: the reconnect re-wait disjunct (a reconnect
  always yields a new client object, so owner identity alone decides it), the `clearSelection` block
  in the connection-update pass (the refresh path does it later against fresher data), and the
  list-failure copy of the owner-eviction filter.
- **One removal was wrong, and review caught it.** I claimed the dock's tab-overshoot branch was
  unreachable after brute-forcing ~15k inputs. A differential sweep of 551,160 combinations found
  **701 divergences** — mine never tried *double* tabs at narrow widths. The consequence is not
  cosmetic: dropping the tab drops the cursor atom with it, so the dock falls back to an empty input
  row and the buffer disappears from view. Restored and pinned.

Review also found two `@mutate` directives pointing at text that no longer existed — one orphaned by my removal, one by an earlier reformat. Both repointed; all 43 directives on the diff now resolve exactly once.

## What the reviews caught that the gate did not

Seven implement PRs went through subagent review with instructions to *apply* every mutation directive rather than read it. Six carried a real finding — including the last, which refuted a claim of mine:

- **#2511** — both checkpoints were never verified at all. Their criteria quoted `// @mutate …`
  without the literal phrase `Mutation checkpoint:`, and the verifier selected on the phrase only.
  The mutations did kill, but only because a reviewer applied them by hand. Fixed in #2518.
- **#2518** — its own directive quoted an expression the formatter had wrapped across two lines, so
  it resolved `target_absent` and never ran; and the mutation it described was a no-op, because
  block-based disjuncts subsumed the text-based ones it targeted. Hand-fixed before merge.
- **#2530** — a directive pointed at a guard my own refactor had deleted, and a duplicated
  `unregistered-project` guard made the surviving one unobservable, so that refusal had *no*
  effective mutation coverage. Both hand-fixed and re-verified.
- **#2533** — refuted my "unreachable" claim for the tab-overshoot branch with a 551k-combination
  differential sweep, and found two directives orphaned to zero occurrences. See above.
- **#2519 / #2531** — clean on this axis; #2531's audit (36 directives, all applied) is what proved
  the salvage below was safe.

The pattern is stable across three sessions: a ticked mutation-checkpoint criterion is the least trustworthy line in a spec, and CI cannot see it.

## Two hand salvages

**Slice 4, subspec 00.** The run finished 00 and then blocked on 01 — removing the `waitState` panel invalidated two `tui-ink-monitor` assertions that 01's scope forbade touching. Re-running resets the worktree, so 00 would have been discarded. Cherry-picked it out (#2519) and widened 01's scope to name exactly those two assertions.

**Dock projection, subspec 00.** The run finished the work and settled `iteration_timeout` before committing — and the timeout left **three** `@mutate` directives applied to production source. They did not surface together: two were restored, the file was copied out, and the copy still carried a third, because the scoped verification was still mutating that worktree minutes after the run row was terminal. Salvage required reversing every directive mechanically. Landed as #2531 after an audit confirmed all 36 directives resolve and kill, with no fourth stranded mutation.

## Friction not worth a seed

- The `--detach` entry run ID reports `completed` while the write row is still live; waiting on the
  printed ID is misleading. Added to the runbook.
- Left-pane and right-pane now derive a pipeline's project differently (first joined run vs
  unanimous), so they can disagree. Recorded in the #2521 review, not seeded.
- A spec subspec whose own acceptance criterion quotes the human-only markers gets classified
  human-only and is never gated (observed in #2517's subspec 00). Cute, and it did not cost
  anything here.
- `bun run fix` in a worktree without `node_modules` fails confusingly; `lint:md` needs the primary
  checkout's install.
