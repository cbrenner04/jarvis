## Verdict — required outcomes

1. **`v2/docs/daemon-host.md` must match shipped `list` behavior.** The IPC contract still documents only `{ sinceMs?, limit? }` and filtered-list prose that refers only to `sinceMs`. Dimension filters changed daemon filtered-path semantics and are cited from `v1-behaviors.md` via `daemon-host.md`, so the doc is now misleading. Per `documentation-standard.md`, spanning IPC contracts belong in `v2/docs/`. After the update, an operator or IPC client reading `daemon-host.md` must see: optional `project`, `branch`, `specPath`, and `status` on `list`; any set filter field (including dimension-only) enters the filtered path, skips fifty-newest terminal retention and invocation-sibling retention, applies conjunctive matching on **durable store fields before row assembly/rollup**, returns newest-first, and caps at `limit` or **200**; exact case-sensitive match rules for project/branch/spec path; `status` filters durable stored status (not rolled-up list `status`). While aligning terminal-status wording, include `interrupted` wherever terminal retention statuses are enumerated if `--status` documents it elsewhere (pre-existing omission, now visible).

2. **Automated CLI coverage for the three non-`status` invalid dimension codes.** The subspec decisions require missing/empty `--project`, `--branch`, and `--spec` to exit `1` with `invalid_project`, `invalid_branch`, and `invalid_spec` respectively **before any `list` RPC**. Implementation and operator docs already promise this; only `invalid_status` is tested today. Add tests equivalent to the existing `invalid --status` case (exit code, stderr token, empty stdout, no RPC sent) so regressions on those guards are caught like `invalid_status` and the guard-inversion acceptance pattern.

**Rationale:** Outcome (1) closes a documentation-standard gap and fixes a broken source trail introduced by the patch. Outcome (2) closes the gap between spec **decisions** (not only the narrower acceptance bullets) and test coverage for symmetric CLI validation.

**No other actuator work required** for this patch: rollup vs durable filtering, filtered-path retention/cap/sibling semantics, exact `spec_path`, CLI-only terminal `status` validation, scan-all-rows filtering, `intent.md` checkboxes, and production test hooks for acceptance guard inversions are consistent with the completed subspec. Optional hardening (case-mismatch negative test, whitespace-only values, `write-behavior.md` table structure) is not blocking.
