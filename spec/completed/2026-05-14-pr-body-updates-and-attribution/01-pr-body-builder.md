# Deterministic PR body builder with narrative preservation

Replace the one-shot body generator with a builder that assembles the
PR body from three composable parts: a deterministic header derived
from `index.md`, a narrative section bracketed by stable markers, and
(in the next subspec) an attribution footer.

## Context

Today the body is produced by `getDeterministicPrBody(specPath)` in
`src/modes/patch/run.ts`, which calls `generatePrBodyFromSpec` in
`src/modes/patch/pr.ts`. The result is passed through `bodyGenerator`
to `ensureDraftPr` exactly once when the draft PR is opened. Nothing
ever rewrites the body afterward.

This subspec introduces the building blocks for repeatable rewrites.
It does **not** wire up the actual update path (that is subspec 03)
nor render the attribution footer (subspec 02) — but it must produce
output that those subspecs can compose with.

## Decisions

- **Three-part body layout.** The full PR body is the concatenation,
  in order, of:
  1. Deterministic header (this subspec).
  2. Narrative section, bracketed by markers (this subspec).
  3. Attribution footer (subspec 02). Until subspec 02 lands, the
     footer stays as today's single-line attribution and is appended
     by `ensureDraftPr` exactly as it does now.
- **Deterministic header content.** Built from `index.md`:
  - The H1 (e.g. `# Live PR body updates and per-commit attribution`).
  - A blank line, then a `## Progress` heading.
  - A line: `N of M subspecs complete`, where `N` is the count of
    `- [x]` linked subspecs and `M` is the count of all linked
    subspecs in the index.
  - A blank line, then a `## Subspecs` heading.
  - The linked-subspec checklist copied **verbatim** from `index.md`
    (preserving `- [ ]` / `- [x]` state and the original link text and
    target). Use the same `parsePatchSpec` `linkedSubspecs` data the
    existing `generatePrBodyFromSpec` consumes, but keep checkbox
    state and original link text/target rather than discarding them.
  - Non-`.md` linked items (pointers to other docs) are excluded, as
    today's `generatePrBodyFromSpec` already does.
- **Narrative markers.** Exactly:

  ```
  <!-- jarvis:narrative:start -->
  <body>
  <!-- jarvis:narrative:end -->
  ```

  Markers each occupy their own line. Content between them is
  arbitrary markdown.
- **Narrative population.**
  - **Initial create path**: when no PR exists yet, the narrative
    body is whatever the existing agent-driven `bodyGenerator` (or its
    deterministic fallback `getDeterministicPrBody`'s prior behavior)
    produces. For this subspec, keep the deterministic fallback —
    the agent-driven generator already exists in the codebase
    (`generatePrBodyFromSpec`) and remains the one source. The
    narrative for now is the existing
    `generatePrBodyFromSpec(specPath)` output minus the H1 (which
    already lives in the deterministic header). If the result is
    empty, the narrative block contains a single line:
    `Auto-generated by jarvis`.
  - **Update path**: when a PR already exists, the narrative content
    is extracted from the live PR body (fetched via
    `gh pr view <branch> --json body -q .body`) by finding the text
    between the start and end markers. If the markers are missing,
    the narrative section is omitted (header + footer only).
- **Builder signature.** Add a new function in `src/modes/patch/pr.ts`:

  ```ts
  export function buildPrBody(opts: {
    indexPath: string;
    narrative: string | null; // null → omit narrative section
  }): string;
  ```

  It returns the deterministic header followed by (optionally) the
  bracketed narrative section. The attribution footer is appended by
  the caller (today: `ensureDraftPr`; in subspec 02: a new helper).
- **Live-body narrative extraction.** Add a helper in
  `src/modes/patch/pr.ts`:

  ```ts
  export function extractNarrative(prBody: string): string | null;
  ```

  Returns the trimmed text between the two marker lines, or `null` if
  either marker is missing. Exposed for subspec 03 to call from the
  update path and for unit tests.
- **No behavior change yet.** This subspec only refactors body
  construction. The first-create path continues to call
  `ensureDraftPr` exactly once with the new builder's output. No
  update path is wired up here.

      signature above.
- [ ] Add `extractNarrative` to `src/modes/patch/pr.ts`.
- [ ] Update `parsePatchSpec` consumption (or add a small helper) to
      preserve linked-subspec checkbox state and original link
      text/target for the header rendering.
- [ ] Replace `getDeterministicPrBody` in `src/modes/patch/run.ts` so
      the draft-PR-creation path calls `buildPrBody({ indexPath,
      narrative })` where `narrative` is the trimmed output of
      `generatePrBodyFromSpec(specPath)` minus the H1, or
      `"Auto-generated by jarvis"` if empty.
- [ ] Add unit tests in `tests/` for `buildPrBody` (header shape,
      progress count, checklist mirroring, narrative present, narrative
      null) and `extractNarrative` (markers present, missing start,
      missing end, both missing, surrounding whitespace).
- [ ] Update existing PR-body tests to match the new layout.

## Acceptance criteria

- [x] `buildPrBody` produces a body whose header section contains the
      index H1, a `## Progress` heading with `N of M subspecs
      complete`, and a `## Subspecs` checklist that mirrors the
      `index.md` linked subspec lines verbatim (including `[ ]` /
      `[x]` state).
- [x] When `narrative` is non-null, the body includes the bracketed
      narrative block exactly between
      `<!-- jarvis:narrative:start -->` and
      `<!-- jarvis:narrative:end -->` markers on their own lines.
- [x] When `narrative` is `null`, neither marker appears in the
      output.
- [x] `extractNarrative` returns the trimmed text between markers
      when both are present and `null` otherwise.
- [x] The draft-PR-creation path in `src/modes/patch/run.ts` uses
      `buildPrBody`. No regression in the existing
      `ensureDraftPr` happy path.
- [x] `bun run typecheck`, `bun test`, and `bun run check` all pass.
