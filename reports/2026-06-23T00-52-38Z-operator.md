## The experiment: pipeline vs hand-authored (#421 vs #433)

Ran the same idea both ways. The pipeline version (#433) materially diverged, and more safely:

- **Per-project only**, no global `modes.patch.ready` default — reasoned that a single global ready command can't serve repos that each define "ready" differently. #421 added global + per-project precedence (over-build).
- **Tokenize + `execFileSync` (no shell)** instead of #421's `sh -c <command>` — independently closed the injection-surface concern I'd flagged on #421.
- **Dropped `skip`** — the plan split it into its own intent and flagged the "ready-means-verified" invariant as a deliberate question; operator confirmed skip wasn't wanted (the real need is a per-project *command*). #421 bundling skip was over-build.

Conclusion: for a self-contained feature the *code* converges, but the pipeline's decomposition and adversarial review caught two pieces of scope creep and a safer exec model. Worth the cost here.
