## The dependency gap — three passes to one mechanism

The most instructive thread of the session, because I got the *why* wrong twice and the operator caught the third.

- **Symptom:** implement runs blocked with `tsc is unavailable … cannot resolve react/js-tiktoken`,
  and in one case (`review-workflow-composition`) an agent ticked **11 of 12** acceptance criteria —
  including *"tests stay green"* — on code carrying **22 typecheck errors**. It could not have run a
  single check it claimed passed.
- **Wrong framing #1:** "a v2 worktree can never resolve `node_modules`." Overstated.
- **Wrong framing #2:** "agents self-install, so it's nondeterministic." Also wrong — I misread
  ready-finalize's install as the agent's.
- **Correct mechanism (operator-caught):** `bun run ready` *does* install (`scripts/ready.ts:210`),
  but `AGENTS.md:40` tells the agent to run `bun run typecheck`/`test:v2` (which never install) and
  **forbids** `bun run ready`. We steer the agent onto the one path that can't provision its worktree
  and away from the one that can; the harness then installs at the end, too late. Deterministic, and
  self-inflicted.
- **The controlled result:** linking `node_modules` and re-running the *same spec with the same agent*
  fixed all 22 errors in one iteration. The agent was never wrong — it was blind.

Seeds #1573 / #1576 / #1584 track that correction trail. The fix (#1590) provisions at worktree creation and is validated live.
