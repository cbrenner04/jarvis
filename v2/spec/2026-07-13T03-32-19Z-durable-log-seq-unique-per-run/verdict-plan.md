## Verdict — refine (design upheld, coverage and rationale need fixing)

The core design — allocate `seq` inside `append()` by re-deriving the run's max from the durable log file and deleting the constructor-time `sequences` map — is correct and no finding threatens it. This stays one atomic subspec. Six refinements are required.

1. **Fix the cost decision; it is factually wrong.** The spec says "Runs emit a handful of events" to justify the per-append read. The storage path is a single global `~/.jarvis/state/logs.jsonl` shared by every run the daemon has ever executed, so the read is O(entire log history) — every line parsed — not O(one run). Restate the decision honestly (per-append cost is proportional to the whole log, which grows without bound because no rotation exists), and state the position on that growth. Note the mitigating context that makes accepting it defensible: `follow()` already calls `tail()` — a full read and parse of the same global file — every 250 ms per active follower, so this adds no new cost class. Recommended position: accept; rotation/pruning is a separate intent, not an invented bounded-backward-scan optimization inside a correctness fix.

2. **Decide malformed-line behavior in the read.** Moving a parse into `append()` puts a `JSON.parse` on the write path, where a truncated or partially-flushed final line would now throw. Existing appends in the daemon's write loop (iteration and boundary events) are unguarded, so this is a new throw site mid-run. Pin the behavior with a decision (skip unparseable lines rather than throw is the reasonable position — a partial line is transient, not corruption) and cover it with an acceptance criterion. Do not overstate the blast radius: the failure-reporting appends are already `try/catch`-wrapped.

3. **Promote the serialization rule to an explicit invariant.** "Fully synchronous, no `await` inside `append()`" is currently phrased as a consequence of the implementation. It is the invariant that makes the fix correct — any future `await` between the read and `appendFileSync` reintroduces this exact bug. State it as a constraint an implementer must not break. Also, for the single-writer-process exclusion, cite the fact rather than assert it (every `openLogSink` call site is in the daemon process; readers live elsewhere) — and confirm at refine that no `openLogSink` caller exists outside the daemon.

4. **Add an acceptance criterion at the operator-visible layer.** Every current AC stops at the log-stream unit boundary, so the spec can go fully green while the bug that motivated it remains unproven. The duplicate `seq` is operator-visible because consumers dedupe on it: `wait` skips records at or below its subscribe cursor and `follow` advances only on `seq > lastSeq`, so a duplicated terminal `loop_finished` is silently swallowed and an in-flight `wait` hangs until abort. Add a daemon-level criterion: a run whose terminal event is appended by a second sink is observed by an in-flight `wait`.

5. **State a position on pre-existing duplicates.** The operator's live log already contains the duplicate `seq: 2` pair. Max-based allocation does not heal historical records. One line either way (accept — affected runs are terminal and no consumer re-reads them for control flow — or repair) closes it; silence reads as unnoticed.

6. **Sharpen AC 1 to the actual bug.** "Concurrently" cannot mean true concurrency (appends are synchronous and same-process), so say what is actually being asserted: two live sink instances, alternating `append()` calls, where one sink was constructed *before* the other wrote. Name the reproducing pair from the daemon — the reconciliation sink coexisting with the write-loop sink. AC 2 half-covers this; fold the construction-order detail into AC 1 so the criteria pin the real bug rather than a generic one.

**Not upheld:** the objection to listing the `LogSink.append` inline contract comment as a documentation update. This is a harness spec where interface structure is the contract; keeping it is fine. The redirect of the doc target from `v2/docs/state-store.md` to `v2/docs/v2-architecture.md` also stands as drafted.
