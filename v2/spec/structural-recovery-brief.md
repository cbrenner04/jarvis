## Why this phase, and where it stands

237 of 376 v2 code commits over the six weeks before the reset were fixes, clustered on a handful of structural seams — terminal state written on the happy path only, config assembled twice with one copy stale, settlement copied then redriven. The recovery's charter: five structural retirements that close whole classes — one dispatch front door, settlement derived from run rows, atomic terminal writes, the module splits, dead-export/test-seam gates.

**As of 2026-09-05 it is mostly working**: since 08-31, 11 of 79 `v2/src` commits were fixes (~14%, was 63%), zero reverts. Closed: front-door chain (#3226 et al.), both module splits (workflow-runner #3380/#3388/#3393, daemon #3364–#3394), mutation-gate P0 chain (4/4), watchdog trio, external-spec chain (#3122), notification-sweep CPU fix (73–98% → 4.6–15%), daemon socket/status honesty (#3468–#3473), CLI retirements (`write`, aliases, `TuiDaemonClient.start`). The remaining bug frontier is concentrated where the one unfinished retirement lives: **chained/linked-row settlement and resume** (the 09-02→09-05 issue wave: #3462/#3463/#3395, #3464, #3400, #3433), plus the external/`plan.commit:false` family mid-chain. 2026-09-06 landed the matcher head lane (#3514), the disposable-lane gates (#3512), and closed the importer-cap fuse (#3513); it also showed the seam is now mostly **operator-visible**: stage rollups disagreeing with durable run rows, and recovery verbs refusing on branches with undone work. The late 2026-09-06 session closed both dependent lanes (#3535, #3538) and the external chain (#3534, #3543), and shifted the frontier again: the remaining defects are no longer mostly *settlement* but **publication** — five distinct ways a lane that finished its work still could not publish, every one hand-salvaged. The keystone is that `iteration_timeout` has never been resumable for an implement lane, so none of those five could recover themselves.

## Operating notes

**Circuit-breaker (per-lane, per-gate).** If a lane (plan / implement / review) needs hand-intervention twice in a row on the same gate, stop routing that lane through Jarvis until the gate fix merges — hand-land the work instead. Re-open the lane only after one clean end-to-end run on the fixed gate. Mirrored in [operator-runbook.md § Circuit-breaker](../docs/operator-runbook.md#circuit-breaker-stop-routing-a-lane-that-keeps-failing-the-same-gate).

**Parallelization (measured 2026-09-06, refined late that day).** Lane count is not the ceiling — seven concurrent lanes ran at load 6-21 with zero watchdog false-kills, and plans fan out freely (3 concurrent, 2 of 3 clean end-to-end unattended). The ceiling is **verification-phase overlap**: three implements reaching diff-derived verification together drove load to 48.8 and timed out all three at exactly 45.1 min, because each verifier spawns up to `MAX_CONCURRENT_VERIFIER_TEST_RUNS` (4) `bun test` subprocesses. Nothing staggers them; hold at two concurrent implements. A `shared/**` implement's gate still runs all six slices and cannot share the machine. And `ready_gate_out_of_scope` is worse than "manufactured by load" — `main` itself fails `bun run test:v2` on an idle machine with a *rotating* set of 30 s timeouts, all green in isolation ([[coscheduled-test-pair-strands-runs-terminally]]), so the base-ref probe can be truthfully right and still strand healthy work. Attribute by process family before believing any ceiling; never run local suites beside a live gate. Approve fan-out gates serially: head lane first, land, then resume ([[plan-bases-off-a-declared-prerequisite-branch]] + [[pipeline-fan-out-lanes-serial-chained-bases]] are the structural answer). **Do not merge while lanes are live** — every lane branched pre-merge is stale-based and its review/repair steps rewrite files the merge landed.

**Land-a-slice.** A multi-subspec spec converges only with immediate re-dispatch after each merged slice, `cleanup --yes --abandon` between. Treating a merged slice as the finish line strands doc subspecs permanently.

**Guards that destroy.** A guard deciding whether to destroy or land something treats every inconclusive answer as "do not act" — `ENOENT` from a sandboxed caller is inconclusive, not authoritative (the socket outage), and a test that asserts a recorded field is not a test that the behavior happens (#3483's consumption bug).

**A `@mutate` annotation that does not kill is worse than none.** Two shipped inside ticked acceptance criteria on 2026-09-06 and both passed every mechanical gate: one where the mutant collapsed a result to `[]` while every assertion over it was `.not.toEqual` or emptiness-tolerant, and one where the annotated line was reachable only through a branch no fixture exercised. Verify a pin by deleting the line it names, not by reading it.

**Plans invent precision.** A criterion naming a test that does not exist passes review and blocks ticking later; verify named tests exist at plan review, and prefer discovery scripts over hand manifests (the #3442 narrowing).
