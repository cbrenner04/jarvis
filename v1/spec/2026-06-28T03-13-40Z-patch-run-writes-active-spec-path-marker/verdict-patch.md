1. Patch preflight must not leave a live `.jarvis.lock` behind when `.active-spec-path` setup fails. The new marker write happens after the patch worktree is created and locked, and this subspec still requires normal git-backed patch runs to remain resumable. Any error after lock acquisition must unwind cleanly so a failed marker write does not strand the worktree in a permanently “in use” state.

2. The change set must stay within the active subspec’s scope: patch preflight should write and refresh `.active-spec-path`, but shared ready-gate behavior must not be broadened here. Adding unconditional `node_modules` bootstrap via `bun install --frozen-lockfile` inside `runReadyAndCommit(...)` changes operator-facing semantics for patch completion, `triage --mark-ready`, `triage --merge`, and committed plan ready transitions, bypasses the existing per-project `installCommand` contract, and is not required by this spec’s acceptance criteria.

3. Durable docs must match the shipped behavior boundary. This subspec requires documenting patch-worktree marker population and skip cases only. If the ready-gate install bootstrap remains, operator docs are incomplete because they still describe those ready transitions differently; otherwise that extra doc churn should be removed with the out-of-scope behavior change so the documentation stays aligned with the accepted marker-only scope.
