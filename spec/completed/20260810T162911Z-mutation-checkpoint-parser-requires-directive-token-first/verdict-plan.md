## Verdict — refinements required

1. **Token-boundary guard needs its own coverage.** The design requires `@mutate` to be a whole token in directive position, but the only checkpoint mutation reverts the gate wholesale to the token-anywhere form, which proves anchoring and boundary together. Add an acceptance criterion covering a directive-position lookalike token (e.g. `// @mutated …`, `// @mutateSuffix …`) yielding zero directives and zero unparseable entries, red when the boundary requirement alone is dropped. Rationale: repo guidance requires each added or modified guard to be individually invertible-to-red; a boundary that no test isolates can be silently removed.

2. **Decide the malformed-first / later-marker case.** The directive body pattern used to parse a candidate line is unanchored and shared with criterion selection, so narrowing only the line gate leaves a line whose directive-position token has a bad body but which contains a later well-formed-looking `@mutate … "…" -> "…"` sequence parsing as a valid directive rather than `malformed`. That contradicts the ledger decision to keep reporting `malformed` for invalid directive-position bodies. The spec must state which outcome is correct and carry a criterion covering it, and must scope any pattern change so criterion-selection behavior elsewhere is unaffected.

3. **Documentation criterion is currently unverifiable.** No rewording workaround passage exists in the operator runbook today (only a generic recovery/workarounds heading), so "removes any rewording workaround" cannot be ticked or falsified. Either name the exact passage to remove (including a source-comment workaround, if that is what the intent meant) or drop the removal clause and require only that the runbook state directive-position recognition and ignored later prose mentions. Rationale: acceptance criteria must be worktree-verifiable and concrete.

4. **Cite the preservation tests the decisions actually claim.** The ledger preserves target verification and enclosing-test/criterion linkage, but the preservation criterion names only basic parse and malformed tests. Name the existing focused linkage and target-absent/ambiguous tests as staying green. Rationale: preservation ACs cite the tests rather than paraphrase; the cited set should match the behaviors the decisions promise to keep.

No split is required — all findings sit on the same parser gate and its documentation.
