- The workflow runner’s execution contract must be internally consistent: the step `role` cannot be documented as the execution-time model-resolution key while the runner validates `role` and then executes caller-supplied `bindings` unchanged. Initial runs and resumes must either execute against the current `agents + AgentModelConfig` resolution for each step role, or the durable docs and step contract must explicitly narrow `role` to validation-only. As written, the docs promise resume-time revalidation/resolution semantics that the code does not enforce.

- Workflow role validation must treat only real configured role entries as present. A step role like `toString` or `constructor` must still fail as missing `(stepId, role, agent)` bindings. The current property lookup can accept inherited object properties, which violates the subspec’s accepted “unknown role as aggregated misses” behavior.

- Resume coverage must prove the behavior it names. A test that closes and reopens `openStateStore(":memory:")` does not verify durable reopen/resume semantics, so the coverage must either use a persistent state-store path or be narrowed to an in-process claim it actually demonstrates. The subspec and runner docs both make resume behavior load-bearing, so the tests need to match that contract.
