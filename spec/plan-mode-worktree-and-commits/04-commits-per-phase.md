# 04 — Phase commits (`plan: interview`, `plan: draft`)

## Problem

Plan mode produces one commit per phase boundary so each phase is
independently reviewable on the PR. This subspec lands the first two
phase commits with placeholder content:

1. `plan: interview` — commits the seeded `intent.md` from subspec 03.
2. `plan: draft` — commits a placeholder `spec/<name>/index.md` and a
   placeholder `spec/<name>/00-task.md`.

The `plan: review N` commits arrive in
`spec/plan-mode-draft-and-review/02-self-review-phase.md`. Real draft
content arrives in
`spec/plan-mode-draft-and-review/01-draft-phase.md`.

## Decisions

- **Commit author and committer.** Use whatever git identity the rest
  of jarvis already uses for commits (i.e. don't hardcode an author;
  rely on the user's git config inside the worktree). Same as patch
  mode.
- **Commit 1: `plan: interview`**
  - Stages `spec/<name>/intent.md`.
  - Subject: `plan: interview`.
  - Body (single line): `Seeded from <file|inline>.` Replace with the
    appropriate word; for file mode, append the source path relative
    to the project root if it lives inside the project, otherwise the
    basename only.
  - Pushed immediately. First push: `git push -u origin
    plan/<name>`.
- **Commit 2: `plan: draft`**
  - Stages `spec/<name>/index.md` and `spec/<name>/00-task.md`.
  - Subject: `plan: draft`.
  - Body (two lines):

    ```text
    Placeholder draft. Real content comes from spec/plan-mode-draft-and-review/.
    Subspecs: 1
    ```

  - Pushed immediately with plain `git push`.
- **Placeholder file contents:**
  - `spec/<name>/index.md`:

    ```md
    # <Title from name>

    - [ ] [00 - Placeholder task](./00-task.md)
    ```

    `<Title from name>` is the kebab-case `<name>` converted back to
    title case (`oauth-login` → `Oauth Login`). Acceptable for a
    placeholder; real titles come later.
  - `spec/<name>/00-task.md`:

    ```md
    # 00 - Placeholder task

    This file is a placeholder produced by plan mode's worktree-and-commits
    skeleton. Real spec content will be generated by the draft phase
    introduced in `spec/plan-mode-draft-and-review/`.

    ## Acceptance criteria

    - [ ] (placeholder)
    ```

    The deliberately-unchecked `(placeholder)` checkbox keeps `jarvis
    run` from treating the spec as already complete if someone
    accidentally points it at this skeleton output. (Note: `jarvis
    run` only accepts `index.md`, so the realistic "accident" is
    running it against the placeholder `index.md`. The unchecked
    item still serves its purpose there.)
- **Push failures.** If push fails (network, auth), do not roll back
  the commit. Surface the git error verbatim to stderr and exit `1`.
  The next `jarvis plan --resume` (subspec arrives later) can re-push;
  for now the user's recourse is `git -C .worktree/plan-<name> push`.
- **No PR opened in this subspec.** PR opens in subspec 05.
- **No agent calls.**

## Implementation hints

- Reuse whatever helper patch mode uses to make and push commits
  inside a worktree. If it bakes in patch-mode-specific message
  formatting, parameterize the subject and body or extract a thinner
  primitive.
- Compute "is intent file inside the project root" with `path.relative`
  and a "starts with `..`" check rather than string prefix matching.

- [ ] Wire both into `planCommand` after `seedIntentFile`. Order:
  interview commit + push, then write placeholder draft files, then
  draft commit + push.
- [ ] Tests:
  - After `planCommand` returns, the `plan/<name>` branch has exactly
    two commits with the documented subjects and bodies.
  - The remote (faked in tests) received both pushes; the first is the
    `-u` form, the second is plain.
  - Push failure on the interview commit surfaces and exits `1`; the
    draft commit is not attempted.
  - Placeholder `index.md` and `00-task.md` contain the documented
    text.

  documented commits, both pushed to `origin/plan/<name>`.
- [ ] No PR is opened in this subspec.

  error visible.
