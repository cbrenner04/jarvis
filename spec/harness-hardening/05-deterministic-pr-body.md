# 05 — Deterministic PR body

## Problem

When the first subspec in a run completes, `runCommand` makes a *second*
agent call to draft the PR body. Three problems:

1. It is an uncontrolled extra cost on every run that opens a PR.
2. It runs immediately after committing and pushing the first completed
   subspec. If that agent call returns `quota`, `model_config`, or `error`,
   the whole run aborts with exit `1` even though the primary work
   succeeded. The repo is left with "subspec done, pushed, no PR." The
   next `jarvis run` does not retry PR creation cleanly because the in-
   process `draftPrEnsured` flag is gone.
3. `src/pr.ts` already exports `generatePrBodyFromSpec(specIndexPath)` —
   a deterministic generator — and nothing uses it.

## Behavior

Replace the agent-driven body generation with `generatePrBodyFromSpec`.

- `ensureDraftPr` continues to accept a `bodyGenerator` thunk, but
  `runCommand` always supplies the deterministic generator.
- Delete `buildPrBodyPrompt` and `getLinkedSubspecHeadings` from
  `src/modes/patch/run.ts` (they only exist to feed the agent path).
- The PR body remains editable in the GitHub UI; nothing prevents the
  operator from rewriting it after the draft opens.
- If `generatePrBodyFromSpec` returns an empty body for a degenerate spec
  (no H1, no subspecs), fall back to the spec display name and a single
  "Auto-generated by jarvis" line.

A run that creates a PR no longer makes any agent call beyond the
iteration agent.
