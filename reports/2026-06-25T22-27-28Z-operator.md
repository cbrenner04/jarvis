## Workflow + tooling + harness observations

- **#555 broke main, reverted.** Its `runMarkdownlintFix` shelled to `npx markdownlint-cli2` (non-deterministic) and failed emit on any non-autofixable violation. Its own gate passed; the identical code deterministically failed 34 `intentCommand` tests once on main (MD041 on frontmatter-led files). Lesson: run-gate-green ≠ main-green when the run shells to `npx`. Re-seeded as `intent-lint-md-autofix-rework` (use the pinned binary). Verify on main, not just the worktree.
- **Over-parallelizing `jarvis run` is self-defeating.** Four concurrent impl runs starved each other's completion gates (each runs all ~1580 tests). Two timed out (exit 8), one exited 1 — all on one flaky test, not bad code. Impl runs must be near-serial. Plans parallelize fine (cheap gate, isolated dirs).
- **`spawn-classification.test.ts` is a load flake** (5000ms bound, ~5001ms under suite load; 6/6 green in isolation). It poisoned every contended gate. Seeded `spawn-classification-test-flakes-under-suite-load` (related to #519).
- **Plan output bugs hit live, both hand-fixed:** review actuator wrote a refined subspec to the repo root (lost `v1/spec/` prefix) leaving the rejected draft at the real path (#549) → seeded `plan-review-actuator-writes-subspec-to-repo-root`; and a plan emitted a stray `repo:` bare-URL line into a spec's own `index.md`, breaking `lint:md` on main (#550) → fixed via #552, and structurally prevented by the plan-does-not-emit work shipped this session (#560).
- **Recovery that worked:** the timed-out/flaked impl PRs (#556/#558/#560) were all fine — re-running their gate in isolation (after reverting #555 and integration-merging clean main) went green; reviewed + admin-merged each.
- **Quota wall mid-session:** the first 5-plan fan-out failed on claude+cursor quota exhaustion with ollama not running; retried after quota returned, capped at ~3 concurrent.
- **Auto-mode classifier blocked issue comments** the seeding task didn't explicitly request; seeds reference the issues and issues stay open, so traceability holds. (Operator: an autoMode.allow entry for `gh issue comment` on triaged issues would close this gap.)
