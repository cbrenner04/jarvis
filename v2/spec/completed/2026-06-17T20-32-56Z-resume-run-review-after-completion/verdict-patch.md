# Verdict — resume-run-review-after-completion

The core design is sound: the review gate at `run.ts:1391` adds `|| resumeReview` surgically without lowering the gate for normal runs, shrink stays correctly gated at `:1388`, review reuses the existing worktree/PR, and the four guards run before worktree materialization. The following are required.

## Required outcomes

**1. The no-PR guard must read a fresh remote ref, not a stale local one.**
The Guard 3 PR-existence probe inspects only the local remote-tracking ref (`origin/<branch>`) with no preceding fetch. The harness's own worktree resolver fetches *before* it performs the identical probe, precisely because the probe is meaningless without a fetch. The new guard skips that step, so on a fresh clone or a second machine — exactly the case where the local worktree is absent — `origin/<branch>` may not exist locally and the guard false-rejects a spec whose PR genuinely exists. This directly breaks subspec 00's own AC #4 ("PR exists but local worktree is absent → resolution proceeds"), the feature's marquee use case. **Required:** the no-PR guard must consult an up-to-date remote view (perform the same best-effort fetch the resolver already uses before probing), so a completed spec with a real remote branch but no local worktree passes the guard and proceeds to recreate the worktree.

**2. Repair the corrupted documentation sentence.**
In `v1/docs/run-loop.md`, the sentence introducing the review-phase flow ("The review phase flow is:") is split across three lines with blank lines inserted mid-sentence, producing broken Markdown that renders as fragments. Docs are part of the work and must be correct. **Required:** the sentence reads as a single, well-formed line. The adjacent new "Resuming review on a completed spec" section is accurate and should be preserved as-is.

**3. Behaviorally test the guards and execution path; do not rely on parse-level tests alone.**
The only tests added exercise argument parsing and the usage string. None verify the runtime behavior that subspec 00 (criteria 2–6) and subspec 01 (criteria 1–7) assert as satisfied: the four guard exits and their distinct messages, that no agent runs under any guard rejection, that review runs with zero implementation iterations while no implementation agent is invoked, that shrink is skipped (no shrink telemetry row), that an already-ready PR is left untouched, and that baseline/final-gate-failure / blocker (`7`) / quota (`2`) exits are preserved. The `runCommand` test harness already drives comparable git-gated preflight guards, so these criteria are testable by the same means. Ticking runtime-behavior criteria on code-reading alone is speculative completion the acceptance contract forbids. **Required:** add behavioral coverage for the four guard exits/messages-with-no-agent and, for the execution path, at least: review-runs-with-no-implementation-agent, shrink-skipped, and idempotent already-ready. Include one assertion that `--max-iterations` under `--resume-review` causes zero implementation iterations (covering subspec 00 AC #7's behavioral claim).
