## Findings and harness gaps

**Two critical bugs caught before merge (not after — nothing shipped broken):**

1. **Mutation verifier was silently non-functional** (#1787). Its `defaultRunScopedTests`
   passed npm script names (e.g. `"test:v2"`) directly to `bun test` as file-pattern
   arguments instead of running them via `bun run <script>`. Since no file matches those
   literal strings, `bun test --parallel test:v2 ...` always finds zero tests and exits 0 —
   every mutation candidate would have been silently misreported as surviving, in both the
   scoped and "full" branches (the latter mapped to an empty scope, which also
   short-circuited to an unconditional pass). Fixed directly (a precisely-diagnosed
   one-function integration bug), with two new tests exercising the real (non-seamed)
   default implementation — the exact gap that hid the bug, since every existing test
   injected a `runScopedTests` seam.
2. **A `triage --merge` dirty-porcelain auto-commit regressed working code** (#1791). It
   removed a `!` from `guard-deterministic-daemon-tests.ts`'s sandbox-unrunnable exclusion
   check, inverting it. Caught by re-running the guard's own test suite before trusting a
   green report; root cause unconfirmed (captured as seed #1792, its own PR).

**Other harness gaps found and seeded live:**

- `jarvis cleanup` (no `--dry-run`) hangs forever — and pins a core — on non-interactive
  stdin. A background invocation from earlier in this session ran **19+ hours at 99% CPU**
  before being found and killed by hand; a real, previously-unaccounted confound behind
  an unknown fraction of this session's gate flakiness (seed #1792, shared PR with the
  autocommit finding).
- `jarvis cleanup --abandon <name> --dry-run` always fails — the CLI's `if`/`else if` flag
  parser only consumes one flag at `argv[0]`, so combining `--abandon` and `--dry-run` (the
  documented usage) never works in either order (seed #1789).
- `jarvis run workflow plan` reuses a stale `plan/<name>` worktree instead of resetting it
  from base (pre-existing seed `plan-workflow-reuses-stale-worktree`) — hit repeatedly this
  session; recovered each time via manual `git worktree remove --force` + `git branch -D`.
- `an-intent-run-publishes-two-prs-for-one-split` (pre-existing seed) — reproduced live: a
  daemon-restart-orphaned run resumed independently after its branch had already been
  merged, producing a duplicate PR (#1788) on a diverged history; closed without merging.
- `daemon-start-list.test.ts` races a closed database under CI load — deterministic 3/3 on
  the PR #1799 CI runs, 100% unrelated to that PR's diff (confirmed by review). A
  fire-and-forget `promoteQueuedRun()` cleanup can outlive a test's `StateStore` close.
  Landed #1799 via manual `gh pr merge --admin` after 3 identical CI failures and a
  confirmed-clean local gate (seed #1800).
- The merged mutation-verifier's own "bounded count/wall-clock" acceptance criterion was
  ticked without being implemented — caught when a daemon-restart-orphaned duplicate run
  (see above) independently added real bounds during its own gate-repair loop, then hit a
  genuine self-detected surviving-mutation failure in that new code. Not merged (PR #1788
  closed); the real gap captured as its own seed (#1789, `mutation-verifier-bounds-unenforced`).
