## The dominant failure mode: specs silent on guard coverage

**Five times** this session, an implement run ticked every acceptance criterion, passed CI and the ready gate, and then failed post-completion mutation verification on a guard clause no test asserted:

| Spec | Flip | Fix |
| --- | --- | --- |
| P0 coverage advisory | `prompts/write/coverage-advisory.md:1` `missing-render-coverage` | #2045 |
| dual-constraint errors | `guard-deterministic-daemon-tests.ts:17` `!file → file` | #2057 |
| run-list aggregation | `run.ts:144` `!firstError → firstError` | #2062 |
| dual-constraint errors (2nd) | `guard-deterministic-daemon-tests.ts:16` `!file → file` | #2062 |
| run-list `--limit` | `run.ts:59` `=== → !==` (flag→message selection) | #2067 |

**The gate was right every time.** In each case the implementation introduced a guard the spec never asked to be covered in both directions, so the verifier could flip it with nothing failing.

`surviving_mutation_failed` is a *flip* failure — it is not handed back to the agent for repair, and `run resume` cannot fix it (resume replays publication; the coverage is still missing). So each one required an operator spec amendment and a full re-dispatch. That is expensive: roughly a third of this session's wall clock.

**Why now.** The prior session's report records these clearing the gate first-try *with review on*. Review was off for this entire session because of the `role_stalled` defect below. This is the concrete, measurable cost of that workaround, and it is the strongest argument for prioritising [`role-stalled-discards-a-committed-write-step`](#seeds-filed).

## Main went red once

Run 30023800942: one failure, `write loop > lets an observed abort win before the watchdog, but not after it`. The commit was **#2057, markdown-only**. Same code passed 24 minutes earlier; passes 5/5 locally. The test races a 5 ms `iterationTimeoutMs` against a real `setTimeout(…, 40)` and asserts the watchdog wins. Seeded with the compounding half: the determinism guard matches only `Bun.sleep` and `await new Promise(resolve => setTimeout(…))`, so a bare `setTimeout` side effect is invisible to it — the guard that exists to prevent this passed it. Main is green as of close.
