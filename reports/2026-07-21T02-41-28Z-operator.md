## Headline finding — `completed` is not trustworthy

Both runs ended `loopOutcomeKind: "surviving_mutation_failed"`, `resumable: true`. For the same row:

- `jarvis run list` → `completed`, empty `error` / `retryable` / `nextAction`
- run log → `resumable: true`
- `jarvis run resume` → `terminal_run: Cannot resume a failed run`
- `jarvis run workflow` → printed `{"runStatus":"completed","loopOutcomeKind":"complete"}`, exit 0

Three subsystems, three answers. The PRs' draft state was *correct*; the run status is the lie. This is the true cause of the operator's note "runs are labeled complete but the PR is a draft with failing checks" — the PR was right all along. Seed: `a-failed-run-is-reported-as-completed`.

The corollary matters for the next operator: **the mutation gate is the healthiest part of v2 right now.** It caught two real regressions that had green CI and fully ticked acceptance criteria.
