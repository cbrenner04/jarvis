## Recurring failure modes (worth their own fixes)

  the exact bug `shrink-invocation-error-preserves-write-work` (#1836) now fixes. Re-run recovered

  Ran strictly serial after the first double-run. A leaked test daemon even destroyed the operator

## Friction / bugs found (seeded or noted)

- **`jarvis cleanup` stranded-owner check is too broad** (`cleanup.ts:323-325`): any
  `~/.jarvis/worktrees/` worktree that merely *contains* the spec file (e.g. one on `main`) counts
  as the spec's owner, so a single unrelated worktree blocked archival of all 8 completed specs.
  Seed: `cleanup-stranded-owner-check-matches-any-worktree-with-the-spec-file`.
- **`jarvis cleanup` needs a TTY** — piped `y` cancels; no `--yes`. Blocks agent-driven close-out.
- **`jarvis config set-agents --help` wrote `["--help"]`** as the agent list (no name validation).
- **Gate errors aren't persisted** — surviving-mutation and completion-commit errors return only to
  a usually-timed-out CLI (completion-commit case seeded #1819; mutation case is the same class).
