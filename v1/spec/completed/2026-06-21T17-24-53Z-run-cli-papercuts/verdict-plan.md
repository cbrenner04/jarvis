## Verdict

Refine the spec. The draft's altitude, scope, and AC shape are sound — all three subspecs correctly target observable outcomes and list `v1-behaviors.md` updates. The defects are factual mis-citations in the Decisions/rationale and coverage gaps where the AC enumeration is narrower than the stated decision. Both let a checklist-following implementer pass every AC while leaving the intent's actual papercut unfixed. Required refinements:

### Subspec 00 (exit code in summary)
1. **Correct the call-site citation.** The rationale claims patch `finalize` "has both the code and the mapped reason in hand" — it does not; `finalize` receives only the reason string. The numeric code and the code→word mapper live one frame up (the `mapExitCodeToReason` call sites in `run.ts`, ~`:313/317`). The chosen strategy (compose `<reason-word> (exit code <n>)` upstream, no renderer/`runSummary` field change) is correct and should stand — only fix the attribution so the implementer composes at the right spot.
2. **Anchor the doc legend to its real source of truth.** The summary's reason word is produced by `mapExitCodeToReason` (the switch in `run.ts`), not by `run-summary.ts`'s interpolation, and its words differ from the iteration-level reason literals. The doc-update AC ("legend maps each code to the reason word the summary prints") must name that mapper as the authoritative code→word table the legend mirrors, or it is unverifiable.
3. **Pin the no-telemetry path.** Both the telemetry and no-telemetry summary branches interpolate the same upstream-composed value, so both get the code for free — but add/extend a test asserting the composed shape on the no-telemetry branch so it can't silently regress.

### Subspec 02 (plan-failure cleanup)
4. **Fix AC2's description of the boundary blocked state.** AC2 asserts the boundary path has "a committed `plan: draft` and an open draft PR." On a fresh plan the boundary branch commits a `plan: blocker` and returns *before* any `plan: draft` commit or draft PR exists. The preserve decision is still correct (a `plan: blocker` commit is pushed, so the branch is non-empty and resumable) — re-justify preservation from that real state and correct AC2's premise.
5. **Close the two pre-commit leak paths.** The checklist omits two failures that occur before any `plan: draft` commit and therefore leak the worktree+branch under AC1's own prose: the `commitPlanDraft` catch (draft commit itself throwing) and the `commitPlanBlocker` catch in the boundary path. Add both to the cleanup enumeration so AC1 and the checklist agree; these are true leaks the intent targets.

### Subspec 01 (`run --help` + audit)
6. **Reconcile audited-command count with AC coverage.** The decision audits 9 subcommands but the ACs verify only 5 (`run`, `cleanup`, `triage`, `review-feedback`, `prompt`); `init`, `config`, `log-server`, `prices` have no AC, and `init --help` currently runs init silently. Add AC coverage for the remaining four (preferred — the intent says "audit the other subcommands"), or narrow the decision's scope to match the ACs.
7. **Pin `--help` precedence for pass-through commands.** For commands that forward leftover args to a downstream tool, state whether a top-level `--help`/`-h` wins or is forwarded, so the audit doesn't silently break an existing pass-through. The implementation *layer* (parseArgs vs. dispatch) may remain unspecified; only the precedence outcome needs pinning.

### Rationale
Spec guidance requires acceptance criteria to be independently verifiable and the enumerated work to match them; where a Decision's scope exceeds its ACs (findings 5, 6) an implementer can satisfy the spec while leaving the papercut live. Where rationale cites the wrong code location (1, 2, 4), the spec misdirects the implementer and — per the preservation-AC principle — risks asserting behavior a reading of the code disproves. These are citation and coverage corrections, not a restructure; the spec's shape is otherwise accepted.
