## Issue #443 — operator-config, not a harness gap

Reproduced on the host: jarvis spawns `claude` with **no** sandbox flag (`v1/src/agents/claude.ts`); the github-only network limit came from the operator's **global** `~/.claude/settings.json` sandbox. ## Workflow / tooling / harness observations

### Worked well

- **codex as a Claude-quota offload.** Mid-session the operator switched `agentOrder` to
  codex-first to spare Claude usage; the schema/backfill/model-tiering specs ran fully on
  codex (gpt-5.5 plan / gpt-5.4 patch) at comparable quality. Config is read at startup, so
  flipping mid-session doesn't disturb in-flight runs.
- **Adversarial plan review repeatedly earned its cost.** The audit spec's first draft graded
  the audit's *shape* not its *correctness*; review caught it (a confidently-wrong audit would
  have passed). The #416 snapshot approach, schema composite-keys, and migration
  classify-by-what-changed all came out of review passes.
- **Pipelining cheap intent steps** alongside heavy runs (disjoint files) cut wall-clock with
  no conflicts.

### Failure modes hit

- **Review-phase quota exit obscures a complete implementation.** model-tiering run exited `1`
  because the post-completion *review* phase exhausted codex quota (and cursor fell over) —
  but the implementation was done and all ACs ticked. The generic `exit 1` hides "code is fine,
  only review/auto-ready failed." Manual-finalized (reviewed the diff, ran the gate, ready+merge).
  **Seeded** as a harness gap (distinct exit/status for review-only failure) — not driven.
- **Bundling `gh pr merge` + a long run in one background command hid a failed merge.** The
  backfill PR #461 merge failed silently (PR still draft at that instant; no-`&&` chain continued
  to launch the next run). Caught only by a final open-PR sweep. Lesson: never bundle a merge with
  a launch; merge foreground, observe, then launch.
- **Route-by-target transitional batch.** This session's specs were authored *pre-flip* under
  `v2/spec/`, so the new by-authored-home `cleanup` archived them to `v2/spec/completed/`. 8 of 9
  are v1-work, so I hand-relocated them to `v1/spec/completed/` — the **last** manual relocation;
  future specs (authored under `v1/spec` after the config flip) archive correctly with no move.
