**Verdict**

1. Add test coverage for the actual leak scenario. Every existing test in `daemon-wait-run-completion.test.ts` either never creates a wait fanout or drives the run to a terminal status before the test ends — which self-terminates the fanout independent of `close()`'s teardown loop. As a result, no test exercises `close()` aborting a still-*live* (non-terminal) fanout, which is precisely the scenario the spec identifies as the leak's root cause ("a run created but never driven to a terminal state"). Without this, the fix's correctness rests solely on the black-box stress loop, which can mask a latent teardown bug if the timing characteristics of CI differ from the local stress run. Add a test that leaves a run in-progress (non-terminal) when the test ends, asserts the fanout map is non-empty going into teardown, and confirms `close()`/`afterEach` tears it down with no dangling waiters or watchers.

No other changes required — the microtask-based abort-and-close chain (via `AbortSignal` → synchronous `finish()` → `finally` closing the watcher) is a sound, deterministic teardown pattern consistent with the rest of the fanout code, and doesn't need to be rewritten to use an awaited/async close.
