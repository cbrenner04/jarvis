## 3. Harness / workflow observations

**Grounding & adversary passes caught real defects — including in my own intents:**

- **harness-transient:** planning grounding found the actual seed-3 culprit `gh pr ready` is a *direct `execFileSync`*, not via `runGhCommand` as my intent claimed → split into async-chokepoint + sync-path subspecs. Adversary caught a **lost-ack idempotency** trap (transient timeout *after* the server flipped the PR → retry hits "already ready" → must treat as success).
- **codex:** resolved my intent's open question — it's an **accounting bug, not adapter inefficiency** (97% cache hit already) — and found a bonus default-model defect.
- **model-defaults:** adversary caught my intent conflating cursor's two maps (CLI-slug vs identity price-key).
- **patch-review:** caught a silent-retry-default bug (production retries had no stderr emitter) and a codex test-traceability gap. Both fixed before merge.

**Failure modes hit (the toil):**

- **Audit integration-merge** (`run.test.ts` conflict): the audit had **silently dropped 2 tests** vs baseline (incl. a real `idle abort not classified as quota` regression-guard). Restored verbatim from git; re-ran full gate sandbox-off. → memory `audit-refactor-may-drop-tests`.
- **Transient-killed plan** (finalize plan died on an opus overload mid-review) → complete-but-dirty plan worktree; operator-finalized by reconciling the index to the actuator's split. *Ironically the exact bug the spec it was planning fixes.* → seeded `agent-transient-retry-backoff` (the agent retry has **no backoff**, so a sustained overload exhausts the cap).
- **Review-actuator hang** (#383 and #390 both rode the 30-min wall timeout in the post-criteria review) → live validation of finalize subspecs 03/04 (extend idle watchdog beyond patch).

**My own operator bugs (logged):**

- **BSD `pgrep -c`** doesn't exist → `pgrep -fc … || echo 0` made every process read as dead (false "run ended"). Fixed to `pgrep -f … | wc -l`.
- **`nohup … &` nested inside the background-task runner** → wrapper returned immediately, run executed untracked. Fixed: run the jarvis command *as* the background task.
- **Heredoc-in-`"$(…)"`** bash quoting broke several commit/PR commands → switched to `-F`/`--body-file`.
- **Untracked wip-intents on the primary checkout** blocked a `git pull` after they were committed via PR. Lesson: seed intents in the PR branch, not on primary.
- All four folded into the runbook.

**What worked:** the chicken-and-egg diagnosis (stale committed `## Blocker` in a worktree → 1s exit); background-run + wrapper-notify; disjoint-file concurrency (never conflicted except the pre-existing audit case); verify-the-adversary-was-resolved before merging (caught nothing un-fixed, but confirmed each).
