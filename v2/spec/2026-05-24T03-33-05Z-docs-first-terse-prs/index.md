# Docs-first terse PRs

Separate two axes that "be terse" currently conflates: terse *communication*
(specs, PRs, commits) versus well-documented *code and durable docs*. Define the
documentation standard and placement policy, require documentation-first behavior
against it in shared prompts (binding both engines), then make machine-generated
PR bodies terse. Foundation -> ordering -> output.
