## The 3.4 miss (stated plainly)

`workflow-wedged-run-killable` does **not** land. Adversarial review + a direct code read proved the `reapable` discriminant is a runtime no-op: every latch tried across four attempts (two codex on a no-bound-subprocess inference; one claude on the operator-sharpened iteration-timeout/orphan events) **coincides with the run terminating** — `write-loop.ts` fires `onReapable` immediately before `finishLoop(...,true)`/`finishIterationTimeout`, so a `(live ∧ reapable)` state is never observable by a real kill (verified: 8×200 kill-polls → 0 reaps; mutation "make the latch a no-op" stayed green across all 1150 tests). **The operator's spec-sharpening (#1749) was part of the miss** — it replaced the original signal with two termination-coincident events. Root cause: a live-but-wedged step needs a **live idle/stall signal** v2 lacks until Wave 4. Reseeded as `wedged-workflow-kill-needs-a-live-stall-signal` with the corrected analysis; the spec carries a `## Blocker` so it is not re-run as-is.
