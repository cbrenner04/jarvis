# Explicit reset flag on implement re-dispatch; unlanded-commits refusal names the continue path

A continuable implement lane (clean, unowned, base-descended, commits ahead of base) continues on its worktree. There is no way to ask for retirement instead, and the unlanded-commits refusal an explicit reset then hits names only hand-finish and `--abandon`.

Order: 00 lands before 01; 01's flag-path wiring depends on the flag.

- [ ] [00-reset-despite-continuable-flag.md](./00-reset-despite-continuable-flag.md) — `--reset-despite-continuable` on `jarvis run workflow implement` forces the retirement path, subject to every existing reset gate.
- [ ] [01-unlanded-refusal-names-continue-path.md](./01-unlanded-refusal-names-continue-path.md) — the unlanded-commits refusal names the continue path before hand-finish and `--abandon`, only where continuation is available.
