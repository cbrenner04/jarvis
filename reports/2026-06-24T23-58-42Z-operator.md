## Workflow + harness observations

**The dogfooding caught its own bug, twice.**

- The `review-incomplete` (exit 11) feature, once merged, immediately and
  correctly classified the runs of its own sibling specs (`auto-ready`,
  `corpus-normalize`) as "implementation done, review couldn't finish" instead
  of a generic error — exactly its purpose.
- The first `quarantine` implementation passed the completion gate with **all
  ACs ticked but zero test coverage** for the new behavior; the review pass
  flagged it but the run errored before the fix landed. Caught on review,
  re-run, landed with 3 real tests. The completion gate only runs *existing*
  tests, so it can't detect that a new AC is untested — a latent gap.

**Failure modes hit (and how recovery went):**

- **npm-dep installs are impossible in a worktree** — `node_modules` symlinks to
  the primary checkout (outside the worktree), so codex (network-blocked) and
  claude (`EPERM` through the symlink) both fail to `bun add`. Blocked the whole
  markdown chain; resolved by hand-provisioning the dep, then letting the agent
  finish. Seeded: `agent-cannot-install-deps-in-symlinked-worktree`.
- **codex auth token revoked mid-session** — surfaced as a fatal exit-3
  (`model_config`) that hard-stops a run rather than falling through to the next
  agent. Dropped codex from `config.json` so runs fall back claude → cursor →
  opencode cleanly; **codex needs re-auth to restore the fallback.**
- **Ready gate flakes under full-suite CPU load** — `sandbox-unrunnable`
  real-process timing tests timed out / failed under load while CI and isolated
  runs were green (`spec-reset`). Partly self-inflicted by concurrency; recovered
  by isolated re-run + CI confirmation.
- **Review actuator non-fast-forward push** diverged the `corpus-normalize`
  branch and blocked auto-ready, forcing a manual finalize of the (clean,
  complete) PR head. Seeded:
  `review-actuator-push-failure-diverges-branch`.
- **Plan re-run throws on a surviving `.worktree/plan-*`** — manual cleanup
  before each retry. Seeded: `plan-rerun-throws-on-surviving-worktree`. This is
  the real friction the misformed `commit-false-rerun-hygiene` seed was reaching
  for.

**What worked well:** the agent-fallback chain (claude quota → codex/cursor picked up implementations mid-run), the plan prerequisite gate (correctly blocked the no-referent worktree-reuse spec), and the plan review pass (caught real correctness gaps — zero-match globs, false "tests stay green" claims, AC contradictions — before implementation).
