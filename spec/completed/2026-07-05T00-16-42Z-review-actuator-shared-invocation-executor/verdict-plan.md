- Make the actuator-only fallback contract explicit. The spec currently relies on readers inferring that review actuator advances on lenient weak-quota and idle-timeout in addition to native quota, while other review-shaped callers may keep different policies. The slice needs to state and pin that actuator behavior directly so the shared-executor migration preserves the intent’s “behaviorally unchanged” requirement instead of silently normalizing to the helper default.

- Add preservation coverage for every surface touched by the shared binding change, not just patch review. If this slice extends `createReviewInvocationBinding`, the spec must also anchor standalone review-mode behavior with an existing test/source path, because spec guidance requires refactor ACs to cite the tests that preserve behavior, and the intent does not authorize regressions outside the actuator caller.

- Clarify the prompt-construction contract at the binding seam. The draft says actuator prompt text is built once and reused across rungs, but it does not state how the shared binding API must preserve that observable behavior. The spec needs an explicit outcome that rules out per-rung prompt rebuild drift, because single-build reuse is part of the current actuator contract and affects persisted verdict-patch consistency.

- Pin the zero-rung terminal path with a task or acceptance criterion. The draft decides that “no actuator agents available” remains a pre-executor terminal failure, but it does not currently verify that outcome. The spec should cover it explicitly so migrating to `executeWithQuotaFallback(...)` cannot accidentally inherit the executor’s empty-input behavior and change review exit semantics.
