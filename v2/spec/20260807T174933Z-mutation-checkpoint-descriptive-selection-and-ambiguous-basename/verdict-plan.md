## Verdict: required refinements

1. **Resolve prefix-first checkpoint AC shapes before narrowing selection.** The dominant corpus pattern (`Mutation checkpoint: in \`file\` test \`title\``, prose about a directive in the pinning file) contains `Mutation checkpoint:` but not the canonical suffix and usually no `DIRECTIVE_PATTERN` in the criterion block. Suffix-only narrowing would silently deselect real checkpoints — worse than the descriptive-prose false positive this spec fixes. The spec must either (a) define and preserve a structured prefix-first shape alongside the canonical suffix and `DIRECTIVE_PATTERN`, or (b) explicitly retire prefix-first, migrate open/completed spec ACs, and prove migrated shapes still select and verify. A decision ledger entry and matching tasks/ACs are required; doc updates alone are insufficient.

2. **Add preservation ACs for every checkpoint selection path that must survive the change.** At minimum: suffix-first (`subspecNaming` / `mutation-checkpoint-regression.test.ts` rows), prefix-first intent-style ACs (if retained), `DIRECTIVE_PATTERN` in criterion text, and existing regressions such as `prose @mutate without a directive-shaped occurrence is not selected` and ticked criteria with directive-shaped `@mutate` still verified. AC-4’s mutation pin on the descriptive-prose regression does not substitute for these.

3. **Address residual false positive when functional AC quotes the canonical suffix template.** Meta-specs documenting `` `file` — `title`; Mutation checkpoint:`` as contract prose (without a linked directive) would still select under a pure suffix guard. The spec must state whether selection requires pin linkage (directive in pinning file, structured prefix/suffix with embedded pin file and title, or equivalent) and cover that edge in an AC or an explicit ruled-out decision.

4. **Extend final verification AC to `bun run test:shared` (or full `bun run test`).** Tasks touch `shared/mutation-checkpoint-criteria.ts`, which feeds plan-review hollow-pin detection (`review-plan-hollow-pin.test.ts`). `test:v2` alone under-scopes `shared/**` per repo CI rules.

5. **Task `write-loop.ts` parity for `ambiguous_pinning_basename`.** `checkMutationCheckpointsAtCompletion` in `write.ts` is tasked, but `blockingUnparseableEntries` in `write-loop.ts` duplicates the blocking filter and must treat `ambiguous_pinning_basename` like `unresolved_pinning_test` (hard-blocking, not repromptable via `repromptableMutationDirectiveBlocking`). Name this seam explicitly in tasks, as prior keystone work did for `inertHeadline`.

6. **Add an integration AC proving production `changedPaths` threading.** Unit AC-1 passes `changedPaths` through test seams; tasks require threading `git diff --name-only <baseRef>` from `checkMutationCheckpointsAtCompletion` and the write-loop reprompt path. A `write.test.ts` AC must show execution-vs-commands `write.test.ts` collision disambiguated via the real completion path (execution-only diff → `caught`, not manual seam injection), not only via `verifyMutationCheckpoints` unit tests.

7. **Specify the `ambiguous_pinning_basename` unparseable contract.** Tasks mention the new reason and candidate enumeration in `describeUnparseable`, but do not define `UnparseableDirective` fields (e.g. `candidates`), which existing fields stay populated, or the operator-facing string shape tests will assert. Add a decision or AC that fixes that contract.

8. **Complete spec-guidance documentation for the new refusal reason.** The spec-guidance doc AC and documentation-updates bullet must replace same-basename-different-dir refusal vocabulary from `unresolved_pinning_test` to `ambiguous_pinning_basename` with candidate enumeration, matching operator-runbook and `v1-behaviors.md` ACs.

9. **Clarify changed-path filtering scope and edge cases in decisions or docs.** State explicitly that parent-directory equality filtering applies to the final candidate set after extension tolerance, not only primary basename hits. Document operator expectations for nested edits under a pinning test’s parent directory, spec-only/docs-only diffs with no overlapping parent dirs (path-qualify or ensure overlap), and untracked paths excluded from `git diff --name-only <baseRef>` (consistent with CI test-scope source).

10. **Acknowledge hollow-pin plan-review side effect.** Narrowed selection changes `detectAtRiskHollowPinsInMarkdown` behavior. Note this in documentation updates (or a brief decision) and ensure `test:shared` hollow-pin coverage remains correct after the selector change.

11. **Correct problem-statement accuracy for keystone over-match.** Guard selection already skips keystone-marked blocks; `Keystone checkpoint:` substring over-match lives in `selectKeystoneCheckpointCriteria`, not guard selection. Rephrase problem #2 so guard and keystone mechanisms are not conflated; keystone canonical-suffix narrowing remains sound.

12. **Rephrase prerequisites to name the live guard-selection bug.** `Mutation checkpoint:` substring `includes` over-match on functional AC is the unresolved guard-selection problem; bare `@mutate` prose without directive shape is already handled today.

13. **Split the subspec into two independently testable subspecs linked from `index.md`.** Shape-based criterion selection (selector, hollow-pin surface, descriptive-prose regression, prefix-first/suffix preservation) and ambiguous-basename disambiguation (`changedPaths` threading, `ambiguous_pinning_basename`, integration tests, refusal docs) are separable surfaces with distinct failure modes; silent checkpoint deselection from (1) can ship while (2) lands. Every task and acceptance outcome from the current monolithic subspec must appear exactly once across the replacements, with every replacement linked from the index. If the refiner keeps a single subspec, preservation ACs for item 2 and an explicit prefix-first decision from item 1 are mandatory before merge — split is the safer default given severity of silent deselection.
