# One work tree for pipelines and ad-hoc runs

Authoritative for implement runs: acceptance criteria, documentation updates, and material decisions in this file supersede `intent.md` where they differ.

## Problem

Ad-hoc `run workflow …` launches render in a second-class "Unattributed" segment below the pipeline tree (`v2/src/tui/tui-monitor-lines.ts`). The segment reintroduces the bug class the tree already fixed with full-flatten + scroll viewport: `monitorSelectableNodeIds` appends the *post-eviction* `unattributedRows`, so expanding a pipeline shrinks the segment budget and silently deletes ad-hoc runs from navigation; and `retainUnattributedSegmentFifo` treats finishless terminals as unevictable must-keeps that crowd out everything else at small budgets. `leftPaneUnattributedBodyRowBudget` computes that budget from painted tree rows, coupling two independent surfaces.

## Decision ledger

- Ad-hoc work items are top-level nodes in the same flatten as pipelines; `buildMonitorPipelineTree` returns `displayNodes` only. Rules out keeping a second row list that the pane concatenates.
- An ad-hoc work item is one workflow-invocation group (its `WorkflowTableRow`, grouping unchanged); a run with no invocation degenerates to a `standalone` row. Rules out one node per constituent run.
- New display-node kind `adhoc` — `{ kind: "adhoc"; id: <representative run id>; depth: 0; tableRow: WorkflowTableRow }`. Rules out reusing `kind: "run"` at depth 0: consumers must tell a stage's run leaf from a top-level ad-hoc row (right-pane pipeline context, `run_leaf` vs `unattributed`), and depth arithmetic breaks once `tui-intent-branch-subtree` adds a tree level.
- Ad-hoc `TopLevelOrderKey` — this is the caller the shipped ordering spec deferred to (`20260807T212915Z-tui-work-tree-top-level-ordering/00-three-bucket-top-level-ordering.md`): `rank` is `running` when any member is non-terminal (`workflowGroupHasActiveMember`) else `terminal`; `createdAt` is the earliest member `createdAt`; `finishedAtMs` is `workflowRollupFinishedAtMs(members) ?? null`. Rules out the representative run's own timestamps — a collapsed group's finish is its last member's finish.
- Ad-hoc items are never `gated`. Rules out mapping `blocked` / `paused` runs onto the gate rank; "needs me" surfacing belongs to `tui-attention-segment`.
- No pane-side retention: every non-queued run matching no stage `workflowInvocationId` becomes a node, and overflow rides the existing scroll viewport. Rules out any replacement budget or FIFO. The daemon's fifty-newest-terminal `list` retention becomes the only cap.
- Ad-hoc rows stay non-expandable this subspec; `e`, `expand`, and `collapse` keep reporting `unattributed`. Deferred to first consumer: ad-hoc constituent-run expansion — pin when a caller needs it. Rules out adding invocation-level expansion here.
- The `unattributed` selection-error code keeps its name and meaning (a run not attributed to a pipeline); only its detection source moves from segment membership to node kind. Rules out folding it into `run_leaf`, which churns the dock's documented codes for no operator gain.
- Detection reads `fullTreeRows`, not painted rows, so an off-viewport ad-hoc selection now reports `unattributed` instead of today's `stale_non_expandable`. A behavior change the deletion causes, not a preserved one.
- Right pane: an ad-hoc selection renders run detail with no pipeline context, suppressed by node kind. Rules out the positional `findLast` ancestor scan, which would attach whichever pipeline happens to sort above it.
- Fixture invariant for the right-pane pin: the ad-hoc row must sort *below* a pipeline row. With no pipeline above it the ancestor scan finds nothing anyway and the guard mutation is hollow.
- File and exported builder names stay (`tui-monitor-pipeline-tree.ts`, `buildMonitorPipelineTree`, `buildMonitorPipelineTreeJoin`). Rules out a work-tree rename, which would stale the `## Prerequisites` of every queued sibling ready-intent.
- `flattenMonitorPipelineTree`/`buildMonitorPipelineTree` drop their unused `maxVisibleRows` parameter. Rules out threading a pane dimension through a builder that never reads it.
- `workflowTableRowMembers` moves from `tui-monitor-lines.ts` to `tui-monitor-workflow-collapse.ts` and is exported. Rules out duplicating it in the tree module; the FIFO being deleted is its only current caller.
- Assertions run through the pure builders (`flattenMonitorPipelineTree`, `monitorLeftPaneTreeRows`, `monitorSelectableNodeIds`, `monitorRightPaneSegmentRows`) and the injected input hook, never rendered ink (`v2/docs/test-writing.md` § TUI test strategy).
- Out of scope: row appearance (`tui-work-row-anatomy`), pipeline subtree shape (`tui-intent-branch-subtree`), the queue segment, and the legacy flat `monitorSegmentRows` / `monitorTextLines` path.

## Prerequisites

- `buildMonitorPipelineTreeJoin` already partitions runs into stage-matched and unattributed candidates via `isUnattributedCandidate` (`v2/src/tui/tui-monitor-pipeline-tree.ts`).
- `compareTopLevelOrderKeys` ranks a generic `{ rank, createdAt, finishedAtMs }` key, so a non-pipeline top-level item reuses it by supplying that shape (`v2/src/tui/tui-monitor-pipeline-tree.ts`).
- `workflowGroupHasActiveMember` and `workflowRollupFinishedAtMs` roll a collapsed group's members up to a status and a finish (`v2/src/tui/tui-monitor-workflow-collapse.ts`).
- `monitorLeftPaneTreeRows` already returns `fullTreeRows` alongside the viewport slice, and `withLeftPaneTreeScrollFollow` scrolls the viewport to the selected row (`v2/src/tui/tui-monitor-lines.ts`).
