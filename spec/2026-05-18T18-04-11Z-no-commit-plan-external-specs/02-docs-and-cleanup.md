# Documentation and cleanup semantics

Document the new no-commit plan storage contract and make cleanup behavior
explicit for specs that live outside target repositories.

## Context

The previous documentation says `commit: false` writes directly under
`project.root/spec/<specDirBasename>/`. That must be replaced. The new contract
is that no-commit plan specs are Jarvis-owned local artifacts under the Jarvis
config directory, and `jarvis run` consumes them through their `repo:` binding.

Cleanup must also avoid pretending these specs are target-repo files. Existing
cleanup behavior archives target-repo `spec/<name>/` directories for completed
worktrees. Jarvis-owned no-commit specs are not tied to a plan worktree or
branch, so cleanup should either leave them alone or expose a separate, explicit
local-spec cleanup rule.

## Tasks

- [ ] Update `docs/plan-mode.md` to describe where `commit: false` plan specs
      are written, how stdout points to them, and why they are not PR-backed.
- [ ] Update `docs/spec-guidance.md` to distinguish committed in-repo specs from
      Jarvis-owned local specs generated by no-commit plan mode.
- [ ] Update `docs/run-loop.md` to describe running external local specs with a
      `repo:` binding.
- [ ] Update `docs/config.md` to clarify `modes.plan.commit: false` storage and
      execution implications.
- [ ] Define cleanup behavior for Jarvis-owned no-commit specs. If they are left
      alone, document that explicitly. If cleanup is extended, require an
      explicit command or flag and avoid deleting local specs implicitly.
- [ ] Remove or revise docs that say no-commit plan specs are written under
      `project.root/spec/`.

## Acceptance criteria

- [ ] Documentation consistently states that `modes.plan.commit: false` writes
      specs to Jarvis-owned storage outside the target repo.
- [ ] Documentation shows a working `jarvis run <external-index-path>` example
      for a no-commit plan spec.
- [ ] Documentation states that these specs require usable `repo:` metadata.
- [ ] Cleanup docs explain whether Jarvis-owned local specs are retained or how
      they are explicitly removed.
- [ ] No docs continue to describe `commit: false` as writing generated specs
      into the target repo's tracked `spec/` tree.
