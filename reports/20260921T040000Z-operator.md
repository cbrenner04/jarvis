## Review record

**8 implementation PRs carried a defect that both the harness gates and CI passed.** The dominant shape is one: a criterion ticked on a test that passes unchanged against pre-change code.

- **#4085**: the output-cap test used a single oversized failing step, so a whole-log tail and a step-scoped cap produce identical text — the test cannot tell them apart.
- **#4088**: the criterion was ticked on a test that hardcoded its row via `commitTerminalRunSettlement` instead of producing it through the changed writer.
- **#4091**: the `run wait` test asserted only that JSON round-trips a string the test itself wrote.
- **#4102**: the legacy-fallback criterion had zero coverage.

Every one was fixed and proven to discriminate before merge, or the criterion was reworded to state what it actually pins.

**#4107 would have let `jarvis cleanup` open archive PRs for unmerged work.** Its only completion evidence was working-tree checkbox state, and the open-PR gate was deliberately bypassed — `if (handLanded) return identified;` returning before `checkArtifactEligibility`. Hardened before merge to evaluate completion against the spec tree as committed on the default branch, reusing `completedSpecEligibility` over a read-only `ArtifactFs` built from `git ls-tree`/`git show`, failing closed.

## A false-positive mutation, and a fix that wouldn't have worked

A `surviving_mutation_failed` on `scripts/test-slice.ts` was a false positive, caught by the runbook's flip-and-test check: neutralising the reported branch made existing tests fail 16/3, so the guard was covered. Root cause was a harness resolution gap — `IMPORTER_SCAN_SURFACE_PREFIXES` was `["v2/src/", "shared/"]`, so `resolveImporterScanRoot` returned null for every `scripts/**` path and no killing test could resolve. Fixed in #4099. Note the first proposed fix — just adding the prefix — would **not** have worked: `defaultListImporterCandidates` enumerates only under the scan root and would never have reached root `test/`. The landed fix is a surface → scan-roots mapping with cross-root de-duplication.

## Two plans rejected on false premises

- **#4105** proposed a 30000 ms per-test timeout to escape a 5000 ms default that does not exist: `bunfig.toml` already sets 30000 and `workflow.test.ts` has no `5000`. A literal no-op that would have ticked its own criteria. The real suspect is `CONNECT_TIMEOUT_MS = 5_000`.
- **#4100** encoded an evidence hunt — up to 20 full `test:v2` sweeps on an idle machine — as implement work, which no run can perform or tick. The defect originated in the ready-intent's own done-condition, so the intent was rewritten as evidence-gated (#4101) rather than patching the plan.

## A wedged daemon that wasn't

A daemon self-handoff looked wedged for hours — 74 `Self-handoff triggered` lines, successors dying as `Daemon process N died during startup`. **I diagnosed it as a permanent unrecoverable defect, and that was wrong.** A still-draining generation held the keyed socket for the targeted digest; the digest then sat still through a long run of spec/doc-only merges, and the handoff converged by itself the moment a source-touching commit moved it. The old process and its socket are gone. Designed behavior.

The real lesson is the digest pathspecs: `v2/src` entire, plus `shared`, `package.json`, `bun.lock` and the tsconfigs. A **test-only** change under `v2/src` rotates the daemon digest and forces a handoff — #4098's two-line `TEST_ISOLATION_CLASS` edit to `workflow.test.ts` did exactly that.

## Friction

- `jarvis run list` returns an empty listing under the agent sandbox instead of erroring, indistinguishable from "nothing live". It produced two false "drained" reports from a Monitor. `jarvis notifications wait` fails loudly under sandbox and is the correct wake primitive.
- Bare `jarvis notifications wait` returns the oldest owed incident across **all** projects on the shared daemon; scope it with `--project jarvis --since <window>`.
- Wrapping `notifications wait` in a loop, or bundling it with another command in one background job, defeats it — the wake sits behind the blocking call. One command per background job.
- CI did not fire for one markdown-only push to #4090 though the workflow has no path filters; it fired normally on the next push. Unexplained.
- Two CI failures were flakes that did not reproduce locally: `v2/src/testing/git-fixture-template.test.ts` (`cpSync` ENOENT on a cached fixture template) and `daemon handoff changeover (real sockets)` timing out at 45 s.
