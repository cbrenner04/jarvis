## 3. Harness improvement priorities (ranked — *read this first*)

### ★★★ 1. Idle-watchdog liveness is stdout-only — it false-kills productive silent work

**The single biggest time sink this session.** The idle-output watchdog measures time since the agent's last *stdout*. But haiku does long stretches of file editing/tool-use with **zero stdout** — so a productive agent looks identical to a hang (`last_output_age_ms=null`). It killed mid-work runs at **both 5 min and 10 min** (e.g. the snapshot-gate agent had written a full subspec + 242 lines of tests when killed). I ended up at a 20-min stopgap, which barely beats the 30-min wall timeout — defeating the watchdog's purpose. **Fix:** liveness must track **file-mtime / tool-call activity**, not just stdout. Kill only when there is *neither* output *nor* file activity. The `watchdog_descendants_alive` signal is already logged. → seed `finalize-complete-but-dirty-run`.

### ★★★ 2. Harness should commit a complete-but-dirty worktree itself

Nearly every meaty run finished its work + ticked ACs but **hung at the finish before committing** (then got idle-killed or rode the timeout), forcing a hand-finalize. The harness already does `git add -A` commits elsewhere (ready-gate commits `check:fix`; #9 commits uncommitted ticks). It should also commit a **complete-but-dirty** worktree and re-run the gate, instead of printing "commit and push from the worktree" and spending an agent turn. This + #1 would have eliminated ~80% of my hand-finalizing. → same seed.

### ★★ 3. Idle-watchdog covers only patch — extend to review/shrink/plan

`idleOutputTimeoutMs` is wired only in `patch/iteration.ts`. A hang in the **review actuator** (seen on run #339, ~16 min silent) or shrink/plan rides the full 30-min wall timeout. → same seed.

### ★★ 4. Transient-retry for the harness's own git/gh ops

Seed 3's run was *complete and reviewed* — it died only because `gh pr ready` hit a **TLS handshake timeout**. The harness's own network calls (`gh pr ready`, push) should retry transient errors, exactly like seed 1 did for the agent spawn. → captured in model-tiering seed's data points.

### ★★ 5. Deterministic model-tiering (config granularity gap)

You can't tier sub-roles today: `modes.patch.agentOrder` sets the model for the *whole* patch mode (actuator + fix-up), not the actuator alone; `plan` can't tier draft vs the review-debate passes. The fix is declared-tier + escalate-on-failure, but it **needs sub-mode role→model config granularity first** (which is why seed 7 can't be implemented standalone). Strong determinism-friendly shape: a fixed **role→model table** (zero inference). → seed `deterministic-model-tiering-policy`.

### ★ 6. Intent-split emit-contract is flaky

The splitter intermittently omits the required `name:` frontmatter / `## Prerequisites`, hard-failing the whole intent run — **3 wasted opus runs** before retries complied. The contract is mechanical; the harness should fill/repair it deterministically (or single-behavior seeds should skip the model turn entirely). → seed `intent-split-emit-contract-flaky`. *(Workaround used all session: hand-promote single-behavior seeds wip→ready instead of `jarvis intent`.)*

### ★ 7. Flaky serial-retry only covers the gate, not the agent's mid-work test runs

Seed 3 added serial-retry at the **ready gate**. But codex ran `bun run test` *directly* mid-work (during the doc-only audit), hit a flaky test, and blocked (exit 7) — the gate's serial-retry never applied. Consider applying the same serial-retry wherever the harness/agent runs the suite, or instructing doc-only subspecs not to run it.

## 4. Model experiment: haiku vs codex/gpt-5 (the switch paid off twice)

Switching patch/plan/review to codex at ~94% Claude usage offloaded the jarvis half of consumption **and** gave a clean A/B:

- **haiku (actuator):** writes correct code first-iteration, but **hangs silently at the finish** and works without stdout (→ idle-watchdog false-kills). Needs hand-finalize often. Tends *not* to over-run the suite on doc work.
- **codex/gpt-5 (actuator):** **self-completed** plan-git-false and intent-no-commit cleanly (`criteria-complete`, in-scope, tests green) — noticeably *less* finish-line hanging. But on a **doc-only** audit subspec it **ran the full suite and blocked (exit 7) on a flaky test** — more eager, stricter blocking.
- **Conclusion:** model choice **shifts which failure modes appear** (haiku → silent-hang; gpt → over-eager suite-running + strict blocks). This is strong evidence that **some "harness" friction is actually model-behavior-shaped** — which is exactly the signal needed to design the v2 model-tiering policy. Worth a deliberate A/B on the *review/adversary* role too (hypothesis: that's where deep reasoning earns its keep — every meaty bug this session was caught in an adversary verdict, not a draft).

## 6. Workflow / operator feedback

- **Hand-promotion beats the flaky splitter** for single-behavior seeds: copy wip→ready + add `name:` frontmatter + `## Prerequisites`, then `plan` directly. Deterministic, free, no flaky intent run. (Plan enforces the same ready-intent format, so the format step is unavoidable either way.)
- **Empty-dir gotcha:** git drops empty `ready-intents/`, so promotion needs `mkdir -p` first (bit me twice).
- **Parallelism gotcha:** don't branch-switch the primary checkout while a just-launched `intent`/`plan` reads it (it reads the seed from the primary at startup) — a race. Merges + `pull` on `main` are safe (no branch switch).
- **Integration-merge safety:** a behind-`main` run's local `git diff origin/main` is misleading (tip comparison); trust `gh pr diff` (computed vs base). Confirmed seed 4's `ready.ts` change survived seed 8's merge.
- **Process inspection must run sandbox-off** — `pgrep` under the sandbox returns "sysmond service not found" (bit me once).
