## Workflow / harness observations

- **Concurrent operator sessions ⇒ constant behind-base.** All 4 impl runs that completed
  after a sibling merge hit "branch does not contain base main; PR stays draft." Each
  resolved with a clean conflict-free integration-merge-then-retest. The structural fix is
  seeded (`run-auto-integrate-base-on-behind`); until it ships, expect one hand-integration
  per impl when another session is live.
- **Localhost log-server healthcheck is a sandbox false-negative.** `jarvis1 plan/run`
  reported "log server unreachable at 127.0.0.1:4310" purely because the healthcheck ran
  inside the sandbox; the server was up. Run plan/run **sandbox-off**. (Cost ~2 wasted
  launches at session start.)
- **Don't bundle admin-merge with a background run launch.** A bundled merge of a still-draft
  plan PR failed silently and the run no-op'd on a missing spec. Merge + verify foreground,
  *then* launch the run. (Plan PRs sometimes land as draft — `gh pr ready` before merge.)
- **Marginal-timeout test flake.** `triage-command.test.ts › --merge classifies all spec
  check statuses` runs ~5.25s against a ~5s timeout; full-suite load tips it over, redding
  the ready gate on correct code. Cost: one hand-finalize (#784). Seeded (#786).
- **Orphaned hang-test fixtures** (`agent-only-hang.sh`, `idle-hang.sh`) were pinning two
  cores at ~96% since Fri/Sat — the Tier-3 self-clean gap. Killed by hand; worsens gate
  contention while alive.
