## Headline: the gate could not pass, and CI could not see it

Every implement run "needing a human finisher" — the third compounding cause named in the consolidation plan — was this. Not agent quality, not a mystery.

**`bun run ready` and PR CI do not run the same suite.** `ready` runs the *aggregate* suite, which routes every agent-mode file through `runV2TestFiles` and its 60s `PER_FILE_TIMEOUT_MS`. `v1/test/run.test.ts` (9467 lines, 242 tests) takes **119s**. Reproduced in exactly 60.0s. CI never runs the aggregate: `ci-test-scope.ts` scopes to `test:v1`/`test:v2` by changed path, and `test:v1 agent` is `bun test --parallel` with *no* per-file timeout. **The one suite the gate depends on is the one suite CI never executes.**

Compounded by a second defect: `daemon-workflow-start.test.ts` (added by #1633) waits on **step 0's** run id then sleeps 25ms, racing the review steps that run under their own ids. Green on Linux CI, red 3/3 on macOS. Bisected green at `74be9092` → red at #1633's own merge commit `f153d9a2`.

`main` was therefore red on the operator machine, behind green CI, for an unknown number of sessions. Recovered by hand in #1644 — nothing could land through the normal path while the gate was red. Design work seeded as `ci-cannot-protect-the-local-ready-gate`.

## Second headline: `ready_gate_repair` fires

The event had **never been emitted once in the harness's history** (`grep -c` = 0 across `logs.jsonl` and `daemon.log`). Root cause: `publishWithReadyRepair` existed, but `workflow-runner` called `publishCompletionArtifacts` **directly**, bypassing repair entirely. The bounded repair loop shipped in #1560 was wired only into the direct write path, never the workflow path — so it was dead code for every workflow run. #1654 routes the workflow through it; three assertions now observe the event on the real runtime path.

Confirmed live on the way: run `140a1063` wrote **two** `loop_finished` events — `complete` at 17:22:15, then `ready_gate_failed` at 17:22:22. `jarvis run wait` returned the first and reported `completed`. 7s is far too fast for the full gate, so it died on `bun run check` and settled without repair. The seed's candidate mechanism 1, with evidence.
