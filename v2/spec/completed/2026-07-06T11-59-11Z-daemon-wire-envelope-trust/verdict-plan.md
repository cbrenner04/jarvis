## Verdict

Five refinements required in `00-thin-envelope-checks.md`:

1. **`parseWaitCompletion` scope is understated.** The decisions list currently names only enum guards (`isRunStatus`, `isWriteLoopOutcomeKind`, `isRunOperatorError`) as removed, but leaves the primitive-shape checks (`iterationsConsumed`, `resumable`) and the conditional per-field result assembly unaddressed. State explicitly that once a well-shaped envelope with `runStatus` present is confirmed, the entire conditional-field-assembly block collapses into a single cast to `WaitRunCompletionResult` — not just the enum checks. This matches the subspec's own stated goal ("thin envelope check... minimal shape needed to route the value") and closes a gap where the draft's task checklist would otherwise under-deliver on its own acceptance criteria.

2. **Real-socket integration case as specified is infeasible/out of scope.** `startDaemon` spawns the daemon as a detached subprocess with no seam to fake the write-loop executor, so exercising `start` over the real socket would invoke a genuine agent CLI — slow, flaky, and out of scope for a wire-parsing subspec. The task/AC must be revised to either (a) seed a run row into the daemon's state store before spawn and exercise only `list` over the real socket, or (b) otherwise avoid driving the real `start`→write-loop path. Update both the task checklist item and the corresponding acceptance criterion to reflect the feasible version.

3. **Clarify deletion scope for guards/constants.** State explicitly that only guards/constants defined locally in `daemon-wire.ts` (e.g. `isDaemonListRunRow`, `isDaemonWorkflowSnapshot`, `isDaemonWorkflowStepSnapshot`, `isDaemonWorkflowStepStatus`, `isDaemonWorkflowStoppedOutcome`, `isNonNegativeInteger`, and the workflow-step enum-table constants) are deleted entirely. Guards imported from other modules (`isRunStatus`, `isRunOperatorError`, `isWriteLoopOutcomeKind`) must not be deleted since they're used elsewhere — only their call sites within `daemon-wire.ts` are removed. This prevents an implementer from accidentally deleting shared code used by other modules.

4. **Trim redundant acceptance criterion.** AC1's trailing clause about malformed nested fields "passing through unchanged" duplicates AC2's claim about test-file contents. AC1 should state only the guard-removal claim; AC2 alone should own the claim about what the shrunk test file covers.

5. **State the trust rationale as an explicit decision, not an implicit assumption.** Add a decision line making explicit why an unchecked cast is safe: client and daemon are the same build/version communicating over a local Unix socket with no cross-version protocol skew, so casting `RunStatus`/`RunOperatorError`/workflow-step enum values without runtime narrowing carries no realistic mismatch risk. This converts an assumption the spec currently relies on implicitly into a reviewable, recorded decision, consistent with the ledger-of-decisions convention.
