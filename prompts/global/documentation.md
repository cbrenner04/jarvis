Before editing code, read the relevant durable docs/specs for the behavior you are changing.
When behavior, architecture, workflow, prompt, or operator-facing semantics change, update docs/specs in the same subspec in the target repo's own durable doc home (per its guidance and existing layout), never a docs path it does not already use; do not defer doc alignment to a follow-up.
If the active subspec explicitly says docs are not required for a purely internal change, do not create speculative doc churn.
