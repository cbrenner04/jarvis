## Why this phase

237 of 376 v2 code commits since 2026-07-15 were fixes, and they cluster on a handful of structural seams — not scattered sloppiness. A pipeline stage *is* a workflow run (both paths end in the same `handleWorkflowStart`); the bug stream comes from what the pipeline layer re-implements around it and from terminal writes that only happen on the happy path.

| Defect class (6-week fix taxonomy) | Fixes | Root mechanism |

| Runner/write-loop settlement + resume honesty | 30 | terminal state written on happy path only |
| Mutation/plan-contract verifier | 26 | churn incl. one full revert |
| Cleanup/worktree management | 27 | dead claims, dirty-tree debris |

The five structural retirements that close whole classes: one dispatch front door, settlement derived from run rows, atomic terminal writes, the workflow-runner/daemon module splits, and real dead-export/test-seam gates.

**Two operator-visible shapes this produced, both mimicking documented incidents whose recovery is destructive:** `daemon status` reports `stopped` for a live-but-saturated daemon (its probe connects and times out), so retrying `daemon start` stacks another spinner that is itself too busy to notice it has been superseded — seven accumulated; and `DaemonReadinessTimeoutError` at 5s is a false negative, the daemon becoming ready seconds later. Diagnosing this took three wrong answers first (store size, machine load, inter-daemon SQLite contention), each killed by a cheap probe: an empty store started in 0.57s and an identical *copy* of the real store in 0.64s, under the same load that made the real one time out.

**Both P2 refactor chains COMPLETE** (see the priority table): `extract-workflow-runner-resume-machines` 5/5 and `modularize-daemon-run-control-handlers` 8/8, documentation subspecs included.

**Gate fix:** [[plan-draft-shape-accepts-repo-relative-stage-layout]] #3385 — `v2/spec/<name>/` staging, the path `AGENTS.md` itself trains agents to use, was rejected while #3212 had closed only the sibling `spec/<name>/` case. Third occurrence. The reviewed intent caught what the seed missed: `preserveStage` counted only `spec/` children and would have **wiped a sound draft** before redraft.

**The publication tail is where work is lost, not the authoring.** Every jarvis implement this session produced correct, complete work and then failed to publish it — `unsupported_resume_context`, `iteration_timeout`, stage wedges claiming `entry_run_still_live` against a durably-terminal run, `ready_gate_out_of_scope` on a base-ref reproduction that was itself load-induced (`completion-commit.test.ts`: 26 pass / 0 fail on main), and `ready_gate_command_missing` whose payload was plainly biome lint output (live recurrence of #3355). Not one produced bad code. This is the brief's opening class — terminal state written on the happy path only — and it is now the dominant tax.

**Land-a-slice, stated properly:** it converges a multi-subspec spec *only* if the re-dispatch is immediate after each merge, with `cleanup --yes --abandon` in between (the merged worktree's `HEAD` stops being a descendant of the new base). Treating the merged slice as the finish line is what leaves specs half-done and their documentation subspecs permanently unlanded.

**A terminal pipeline strands a sound plan draft.** When a plan stage settles `invocation_error` and the pipeline goes terminal, `pipeline recover` refuses `stage_not_recoverable` and resume refuses terminal pipelines — a complete 5-subspec draft in `.jarvis-plan-stage/` was reachable only by hand-copying it out (#3389). Worth a seed if it recurs.

**Parallelization, re-measured at seven concurrent implements (load 119):** three fell over, but **no branch was lost** — every failure was a settlement-tail failure over complete work, recoverable for the cost of a push and a PR body. The ceiling is not agent capacity but how many lanes sit in their **ready-gate phase** simultaneously, each spawning ~20 test workers. Two lanes that produced zero commits across five timeouts were circuit-broken.

**Contention manufactures false failures at every layer, including diagnosis itself** — a suite green alone and red beside two others, a CI timeout blocking a PR three times while passing 57/57 in isolation under heavier load, and an idle-detection monitor reading a timed-out `run list` as "no lanes running" (the runbook's "an empty query result is not evidence", reproduced live).
