## Verdict: Required Refinements

1. **Restore the aggregate-error contract.** The spec decision states the loader "collects every hard-error violation across all agents/roles/rungs and returns them together, not fail-fast on the first one." Currently, duplicate-agent-name errors cause an early return (`agent-model-config.ts:142-145`) before any per-agent role/rung validation runs, so a file with both a duplicate name and an independent missing-role or malformed-rung violation only reports the duplicate. Fix: accumulate the duplicate-name check into the same `errors` array without short-circuiting; only bail early on the paths where there's no parsed data to iterate (JSON parse failure, non-object top-level). Add a test exercising duplicate names combined with an independent violation to prove aggregation actually holds.

2. **Make wholly-missing-agent errors consistent with the "name agent and role" contract.** Per the spec, "Missing `(agent, role)` for a required role on a project-configured agent → hard error naming the agent and role" — this applies regardless of whether the agent entry is entirely absent or present-but-incomplete. Currently an agent absent from the file gets one generic `missing agent entry: X` message (line 159-161), while an agent present but missing a subset of roles gets one named `agent X: missing required role R` error per role. Fix: when an agent entry is wholly absent, emit one `missing required role` error per required role, matching the format already used for the present-but-incomplete case.

**Rationale:** Both are contract breaks against explicit spec decisions, not style preferences — the first silently drops real load errors (defeating the purpose of aggregate reporting for a hand-edited file), and the second produces an inconsistent error message shape for what the spec treats as the same underlying condition (a missing required (agent, role) pair).
