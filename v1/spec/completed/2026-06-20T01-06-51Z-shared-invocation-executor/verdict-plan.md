# Verdict

The intent is sound and the per-path decomposition (one subspec per path, byte-identical/exit-code/telemetry acceptance criteria) is the right cut and should not change. The defect is localized: **subspec 00 specifies the shared binding seam against plan's single-call paths alone, while the binding must serve four structurally divergent consumers. Its lone deferral (`allowLenientWeakQuotaFallback` supply) covers the smallest divergence and leaves the load-bearing ones unpinned, so 01–04 would build call sites against a signature 04 must then reshape — retroactive, not additive.** Refine 00 (and the three places below) before any call site lands.

## Required refinements

1. **00 must pin the binding seam with all four consumers in view, not just plan.** The factory contract must account for the axes that genuinely differ per path, so that 01–04 are additive migrations rather than re-openings of 00:
   - **Per-path stderr emitter.** Three distinct emitters exist (`plan:`, `intent:`, `${agent.name}:` prefix) and review emits none (it fires `onQuotaRotation`). A single internal `emitPlanAgentQuotaFallback` cannot satisfy the byte-identical stderr criteria across paths. State that emission is injected/owned per consumer.
   - **Per-path telemetry sink.** Plan paths call `recordAgentAttempt`; intent-split records no per-attempt telemetry; shrink/patch/review write `patch_phase` rows. "The binding owns per-attempt telemetry" cannot hold uniformly — state that the telemetry sink is per consumer.
   - **Per-consumer spawn options.** `additionalReadDirs` (draft/review/verdict-actuator) and watchdog wiring + `abortKillGraceMs` (patch/shrink) are not carried by `invoke({prompt,cwd,signal})`. Resolve explicitly (e.g., factory closes over per-consumer spawn options so `invoke` stays narrow), rather than leaving it implied.
   - **Per-rotation side effects run inside `invoke`.** intent-split's `resetIntentStageDir` must execute before each spawn. 00/01 must name that such per-rotation effects live inside the binding, or 01's fan-out regresses.

2. **00 must resolve patch's spawn/classify split explicitly, and 04 must follow from that resolution.** Patch's classification guard (`noIterationProgress`) is computed only after the iteration body, so a binding whose `invoke` couples spawn→porcelain→classify cannot serve patch. Either 04 is a near-no-op (patch keeps calling the two already-shared functions) or it contradicts 00's coupled `invoke`. 00 must expose spawn and classification as separable steps (or a classify-time guard thunk) so patch interleaves its iteration body without a second classification path. Move this from a "first consumer" deferral into 00's pinned contract — it is the headline structural decision, not a tail detail.

3. **00 must specify the empty-`agentOrder` outcomes.** The executor returns `final: null` uniformly for empty bindings, but intent-draft and intent-split short-circuit to `model_config` results with *different* messages (`plan:` vs `intent: modes.plan.agentOrder is empty`), while other paths fall to the defensive exit-2 path. State how the caller reproduces each path's existing empty-order message rather than leaving the null-final mapping to assumption.

4. **Pin the generic-`T` / rich-ok-result capability in 00 (clarification).** The executor is generic over `T extends InvocationResult` and preserves the result untouched; `InvocationOk` is only the default. A one-line statement that a binding may use an ok variant carrying `usage`/`cost_usd` removes the false impression that cost/usage vanish through the seam. Likewise note in 02 that review's `onQuotaRotation`/`onAllAgentsQuotaExhausted` and `spawnResult` access live inside the binding's `invoke` (where `spawnResult` is in scope) — consistent with 00's rule against threading `spawnResult` through the executor's generic type. These are wording tightenings, not redesigns.

5. **Correct 03's stderr wording.** Shrink's rotation line uses the `${agent.name}:` prefix plus a `result.stderr` passthrough; only contract/exhaustion lines use the `shrink:` prefix. 03's prose ("the existing `shrink:` fallback stderr line") would steer an implementer into the exact regression its byte-identical criterion then fails. Fix the description to match actual output.

6. **Align the intent's "one implementation across all four paths" framing with patch's actual sharing.** Post-refactor, patch shares two already-shared functions (`agent.run` + `applyQuotaFallbackWhenAllowed`) and gains little new unification; 04's own "shares the spawn+classify call only" is the honest statement. Adjust the index/04 framing so reviewers don't expect more unification than patch can structurally accept. Relatedly, since 01–03 defer their v1-behaviors note to 04, ensure 04's documentation entry describes what actually changed (plan/review/shrink routing through the executor; patch sharing the binding only) rather than overstating patch.

## Rationale

The byte-identical-output, exit-code, and telemetry acceptance criteria are the real backstop and are well-formed — but they are *tests*, not a design. Where 00 under-specifies the seam (emitter, telemetry, spawn options, side effects, the patch spawn/classify split), an implementer satisfies the criteria only by re-deriving the abstraction mid-migration, which is exactly the unify-then-diverge trap the intent's decisions warn against ("rules out a parallel quota-classification/spawn implementation"). Spec guidance requires each subspec be one independently reviewable change; with 00 unpinned across its consumers, 01–04 are not independent — they retroactively constrain 00. Pinning 00 with all four consumers in view converts the deferral that currently hides the divergence into an explicit contract, making 01–04 the additive migrations the spec intends.
